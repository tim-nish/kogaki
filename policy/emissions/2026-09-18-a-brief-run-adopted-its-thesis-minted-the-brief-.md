## Trigger — what happened

A /brief run adopted its Thesis, minted the Brief, and then died inside the PostToolUse advance while the compose_path judge was being re-asked. Afterwards the only admissible read, run --status, printed "Position: advancing", and a complete, valid judge record sat beside the run under a .partial name that nothing ever reads back.

## The learning

A status read that reports progress must distinguish a run that is still moving from one whose only mover has exited. Where the thing that advances a run is a short-lived process outside the run's own control, the run's state on disk cannot tell the two apart: the last recorded position is the same whether the next step is about to happen or will never happen again. Have the status read name its evidence of liveness, or say it has none, rather than printing a word that describes both. The same discipline applies to work products left half-named: a record written under a temporary name so that existing means validated is correct, but a complete record stranded there is work that was done and cannot be handed on, so the reader is owed a line saying it is there and why it does not count.
