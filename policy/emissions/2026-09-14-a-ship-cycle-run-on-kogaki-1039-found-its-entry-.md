## Trigger — what happened

A /ship-cycle run on kogaki#1039 found its entry Issue carrying a standing Blocker whose named end is in another repository (claude-toolkit#1047's relink verb). The owner asked for the hold to be recorded on an end condition a later pass could check mechanically. Every condition form the recording instrument admits refused it: the two derived forms run a read in this repository and returned no edge, the path form takes a repo-relative path while the missing carrier is a verb in another repository's tool, and the fourth form names no end at all — which is what the row already carried.

## The learning

When a gate's condition vocabulary is built entirely from reads scoped to one repository, a genuine cross-repository dependency has no expressible end condition, and the gate degrades to the one form that names no end. The failure is invisible because that form is a legitimate member of the vocabulary: the row is written, the pass is graded, and nothing reports that the condition can never be evaluated. The owner's instruction to state a checkable end was not a wording problem but an unreachable arm, and asking for one produces either a refusal or a fabricated operand. A condition vocabulary owes a form for dependencies whose resolution the recording repository cannot observe — or it owes a declared report-only pointer that says so, rather than a no-end row that reads like an ordinary hold.
