## Trigger — what happened

A rule was fixed correctly on the surface where it failed, and written into that surface's own governing document. Three days later a second, unrelated surface reproduced the identical failure — because the rule bound only the place it was written. The obvious next move was to write the same rule into the second document too.

## The learning

When one rule needs writing down a second time, that is evidence about where the rule lives, not about how many places need it. Each per-surface copy is correct, passes its own review, and leaves the next surface unprotected by construction — so the count of successful implementations is the signal, and no per-surface review can see it, because the property is cross-surface. Site the rule once, somewhere every member passes through, and have the surfaces cite it. Membership should follow from what a thing IS rather than from a list someone maintains, because a list has to admit anything it fails to name.
