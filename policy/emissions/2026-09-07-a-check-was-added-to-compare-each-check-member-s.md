## Trigger — what happened

A check was added to compare each check member's admission record against the cases the member actually registers. Its first run named the check's own file as under-described: the pattern that finds registration calls matched the call written whole in the new rule's explanatory prose, so the file became a member of the set it searches. The same run also settled the pattern's shape by measurement rather than by reading: requiring the literal registration id fired on 13 of one member's 35 ids, every one of them already described, because the ids disambiguate reused letters while the record speaks in letters; comparing the id's letter stem instead fired on exactly the three cases the record genuinely never mentioned.

## The learning

A rule that searches files by a textual pattern is itself a file the rule searches, so its own explanation is a source of false members — the repair is to write the pattern's name in prose without the form the pattern matches, and to declare that limit beside the pattern rather than rely on nobody adding prose later. And when a record and the artifact it describes use two different naming vocabularies on purpose, the comparison between them has to be measured before it is built: the obvious literal comparison was wrong by 13 of 35 and would have read as a record defect rather than as a false red, while the weaker comparison was right by exactly the three real omissions. Measuring which comparison fires on what is cheap and is what separates a check that finds defects from one that finds its own convention.
