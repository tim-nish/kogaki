## Trigger — what happened

A /brief run on the agents tag's G1-2 set composed all three Thesis candidates as the ABNORMAL no-served-rendering marker, byte-identical. The seam was reachable and exit 0 throughout: gateway-query.mjs answered every call. What had moved was the shard NAME. kogaki forms gloss shard addresses as <namespace>/<tag> — 'lessons/agents' — and the substrate now serves them windowed, as 'lessons/tag=agents,window=2026-08'. The windowed form returns an 81KB hit carrying every slug the run needed; the unwindowed form returns the miss shape. Nothing under src/ contains the string 'window=', so every gloss address kogaki forms is currently a miss. A 2026-09-06 emission had already seen the same calls miss and attributed it to a different relocation, so the address drift went six days unnamed.

## The learning

A consumer that reads a served surface holds two assumptions, and only one of them is checked by anything: that the seam answers, and that the name it asks for is still the name the surface serves. Reachability monitoring covers the first and is silent on the second, because a miss for a name nobody serves any more is a well-formed successful answer — exit 0, a valid response shape, a real pin. The failure then surfaces far downstream as absent CONTENT, where it reads as the material being missing rather than as the address being wrong; here it reached an owner-facing gate as three identical fault markers offered as things to adopt. Where a consumer composes an address from parts rather than reading it from the surface's own listing, that composition is an unversioned coupling to a naming scheme the other side is free to change. The cheap guard is to ask the surface what it serves - the listing call that enumerates names - and to treat a total miss across every address a run forms as an address fault rather than an empty corpus, because a corpus that lost every entry and a scheme that renamed every entry are the same observation.
