## Trigger — what happened

A /ship-cycle run on kogaki#915 opened its pull request, then had its typed merge act refuse on a session context bound. Two exit grades looked available: the defined exit 'merge-frontier-hold' (held at merge, a pull request open, a named blocker) fit the observable facts exactly, and the run was still a failure.

## The learning

When an exit vocabulary defines its members by one condition each, a stop can satisfy a defined member's wording while belonging to none of them — and the defined member is the flattering reading, so it is the one a run drifts toward. The discriminator is not the observable state but WHAT the member was defined to distinguish: 'held at merge with a pull request open and a named blocker' names a blocker about the PULL REQUEST, and a blocker about the SESSION satisfies its words while defeating its purpose. Read a defined exit's condition as the thing it was written to separate, not as a predicate to match; where the two come apart, the stop is a failure with a typed cause. The observable signature of getting it wrong is a run that ends short of the frontier and renders as a legitimate outcome owing nothing, which is exactly the shape the grade was introduced to end.
