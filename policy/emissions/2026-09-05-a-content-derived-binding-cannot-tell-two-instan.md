## Trigger — what happened

A gate capture bound itself to a digest of the options it was offered, so an answer given at one rendering could not certify a choice at another. The declaration and the capture files were named after the DIRECTORY holding the run state. A test that drove two entries into one directory found that both runs shared one declaration and one capture — and the digest guard could not see it, because both entries were over the same settled input and therefore composed identical options and an identical digest.

## The learning

A binding computed from content identifies the content, never the instance. So it separates two instances exactly when they differ and fails exactly when they are alike — which is the case you need it for, because two runs over the same input are the pair a reader is least able to tell apart by eye. Where a record must belong to one particular run, the key has to name that run: a name derived from the workspace, the directory, or the inputs is shared by every sibling that happens to look the same. The failure is silent and reads as success, since the guard fires correctly on every case where the two differ.
