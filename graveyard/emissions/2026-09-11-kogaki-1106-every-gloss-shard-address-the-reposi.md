## Trigger — what happened

kogaki#1106: every gloss shard address the repository formed had been a miss for days, because the served surface renamed its shards by adding an axis and a miss is a well-formed successful answer

## The learning

Monitoring that a lookup seam ANSWERS is silent about whether the name being asked for is still served. A request for a name nobody serves any more comes back as a successful response — a real pin, a valid shape, exit 0 — and the absence only appears far downstream, where it reads as the material being missing rather than the address being wrong. The repair is not to correct the name: a consumer that composes an address from a template encodes whatever the naming scheme happened to be, so the next change to the scheme reproduces the same silence one axis later. Derive the address from the surface that discloses which addresses exist, so an address can only exist because it was disclosed; and give a run whose every address went unmatched a report distinct from a corpus with nothing in it, because a corpus that lost every entry and a scheme that renamed every entry are otherwise the same observation and only one of them is repaired by fixing a name.
