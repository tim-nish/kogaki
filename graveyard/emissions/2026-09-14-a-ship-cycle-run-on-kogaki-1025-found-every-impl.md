## Trigger — what happened

A /ship-cycle run on kogaki#1025 found every implementation conjunct already carried — seven closed children, green checks at head, and live runs whose every transition named the hook that executed it — while the Issue could still not be closed by the run, because its close condition named an owner confirmation. The run had no implementable work and no failure to report, and the two readings available to it (grade the empty frontier a failure, or close on its own reading of the evidence) were both wrong.

## The learning

An acceptance conjunct that names a human confirmation is not work, and a run that treats it as work misgrades itself either way. Where the remaining conjunct is a person acting, the run owes the person the evidence and a gate, and nothing else: it assembles what the conjunct would be discharged against, presents it, and lets the click be the discharge. Reading the empty frontier as a failure says the run stopped short when it finished; closing on the run own reading of the evidence substitutes the party whose account cannot be the evidence for itself. The design question that separates them cheaply, asked at admission rather than at the close: for each acceptance conjunct, who executes the act that discharges it — and if the answer is the owner, the run plan already ends at a gate.
