## Trigger — what happened

I replaced a hand-kept list of three related things with code that finds them automatically, so a fourth would be covered without anyone remembering. The rule I used to find them was that their names all end the same way. On its first run it also picked up something unrelated whose name happened to end that way too -- a different kind of thing entirely, which would have been checked as though it were a member. I then renamed the three to share a beginning that nothing else uses, so joining the group became a deliberate act rather than an accident of spelling.

## The learning

Replacing a hand-kept list with automatic discovery is usually right, and the discovery rule is then the thing to get right, because it is doing the work the list used to do. A rule based on how names end is the easy one to reach for and the easy one to over-match, since endings are frequently shared by things with nothing in common. Prefer a marker that exists only to mark membership -- a distinctive beginning, an explicit registration -- so belonging is stated rather than inferred from spelling that was chosen for other reasons. Run the discovery and read what it found before trusting it: mine surfaced the wrong member immediately, which is the cheapest possible moment to learn the rule is loose. And keep the honest limit in view -- discovery makes joining explicit, it does not make omission impossible, since something named outside the marker is still invisible.
