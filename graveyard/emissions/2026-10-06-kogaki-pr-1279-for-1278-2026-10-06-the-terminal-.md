## Trigger — what happened

kogaki PR #1279 (for #1278), 2026-10-06: the terminal review round marked two findings 'should [resolved]'. The merge read the review status as round-owed with both rounds spent, and only an owner bypass click merged it. Separately, the worker's new concurrency check passed locally and failed with no claude on PATH, because resuming a Brief run resolves the judge binary before any state work.

## The learning

The review tool's parser accepts one way of writing a finding's state. A reviewer that writes it another way, such as '[resolved]' in brackets, gets that finding counted as open with no answer, and at the last allowed round nothing can clear it except the owner's bypass. When the finding-grammar hook is not installed in the review worktree, nothing catches this before the report lands. The tool's own suggestion to re-post the report does not help, because the same text parses the same way. A check that resumes a Brief run needs a stub judge (KOGAKI_JUDGE_CLI) even if it never reaches a judgment call, because the resume resolves the judge before anything else. Without one the check passes on a machine that has claude installed and fails in CI.
