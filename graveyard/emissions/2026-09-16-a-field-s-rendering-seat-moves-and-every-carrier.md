## Trigger — what happened

kogaki#1126 moved the Candidate gate's figure clause and reader-experience prose from an option's label to its description, and declared a new short-name field for the label. The suite stayed green through the move, and two review rounds still found four separate carriers left naming the old seat: a registry row stating the superseded rendering beside the new one, two refusal messages telling the composing party the label IS the prose it no longer renders into, a vocabulary-tripwire exemption still attached to the label the exempted tokens had left, and a recorded mutation trial that could no longer reproduce because the text it blanked no longer carried the leak.

## The learning

When you move a value from one place on the screen to another, the code that renders it is the easy half. The hard half is everything that merely TALKS about where it used to be: the error message that explains the field by naming its old position, the exemption that was scoped to the old position and now licenses something in a place nothing writes to, the record that states the old rendering next to the new one, and the note recording a past test that no longer tests anything because the thing it broke has moved. None of these fail. The tests pass, the feature works, and the only thing that is wrong is the text a later reader uses to decide which position is live -- which is exactly the text they will trust. So when you move a rendering seat, search for the old seat's NAME rather than for the code that wrote it, and treat every mention as owing either a move or a deletion in the same change.
