## Trigger — what happened

kogaki#722 required deleting a 20-file corpus that git could not preserve: the directory is gitignored with zero tracked files, so unlike its sibling corpus in another repository — where every file survives at every pinned sha and deletion was therefore record-free — this copy was the only copy. The issue set three acceptances in a strict order: run a guard over every file, RECORD the guard result on the issue, then delete. The guard passed 19 of 19. The twentieth file looked like the one exception a real guard finds, and its own header said otherwise: generated by a tool, a rendering and not a source, nothing parses it back — and it was already stale at 16 of 19 rows.

## The learning

When a deletion destroys the only copy, the record that replaces it is a DELIVERABLE with its own acceptance, and its ordering relative to the destructive act is the whole of its value — a preservation record written after the thing it preserves is gone can only describe what someone remembers. The transferable part is what belongs in such a record, because the obvious answer is wrong in both directions. Copying the bodies wholesale reproduces the residue the deletion exists to remove, and recording only what the issue asked for can silently drop the one thing the surviving carriers do not hold. The test that separates them is per-field: for each field, name the carrier that will still hold it tomorrow. Fields whose substance is discharged into a closed issue need a pointer and not a copy; fields that are CORPUS-LEVEL rather than per-item have no such carrier by construction — a dependency edge belongs to neither endpoint, so five edges here would have vanished with every individual issue intact. And a guard of this kind owes an explicit statement of what it does NOT establish: it tested that each bound issue was closed, never that the issue text reproduced the file body, and no instrument available could test the second. Saying so in the record is what stops a later reader treating a passed guard as a completeness claim it never made.
