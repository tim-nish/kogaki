## Trigger — what happened

A /ship-cycle run on kogaki#1111 found the entry issue under a LIVE claim held by another session. The typed claim refused, and reclaim refuses a live claim always, so the run halted at the observation stage before dispatching anything.

## The learning

Two acts can write the record a close reads: the pass, which is derived from GitHub state, and the Blocker, which is derived from a native blocked-by relation or a verified absent path. A run stopped by a machine-local lease matches neither. Nothing about the issue on GitHub has changed, and no relation exists to read, so the pass refuses for want of an outcome and the Blocker refuses for want of an edge. The close then refuses for want of a record. The gap is not that the run ended badly but that the vocabulary for why a run ended is drawn entirely from the substrate's own state, while one of the real reasons a run stops lives on the machine instead. A carrier exists for the halt at preflight; the same row is owed at the observation stage, where the lease is read.
