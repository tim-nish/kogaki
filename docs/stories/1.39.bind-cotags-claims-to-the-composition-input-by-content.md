## Story

As the owner relying on Terrain's composition bound,
I want `cotags` to refuse claims whose members were not served by the bounded read,
so that `.claude/skills/terrain/SKILL.md:195`'s hard line — *"Compose from
`compose-input`, never from the whole survey"* — is enforced at the layer where it can
be broken rather than stated in instruction text a session is free to satisfy nominally.

## Context — what is unobserved today

`cmdCotags` accepts `--survey`, `--tag`, `--claims`, `--subdivisions` and `--connective`
(`terrain/terrain.mjs:575-591`) and records **nothing** about how the claims were
composed. `checks/check-terrain-composition.sh` exercises `cotags` end to end — the
`FIXTURE` block at `:90`, `:141`, `:172`, `:196`, `:212`, `:275` — and observes only its
outputs. So a session composing from the whole survey produces output indistinguishable
from one composing from the bounded read.

The slot was deferred by PR #198; with kogaki#183 and kogaki#194 both closed, it lived
only in a merged PR body until this sitting.

## Acceptance criteria

**AC1 — `compose-input` emits a composition pin carrying the SERVED MEMBER SET.**
Given a `compose-input --survey <record> --tag <T>` invocation,
when it produces its bounded read,
then it emits a composition pin carrying the tag, the survey record's pin, and **the
member set it served, per group**.

*Amended by §11 v10 (2026-08-07).* This criterion read "a **digest** of the member set"
until the spec sitting found that a digest supports **equality**, not subset, and can
name no offender — so it could not deliver AC3, which the same section states. The
property is load-bearing and the digest was the mechanism, so the mechanism gave way
(`consulted: product-lab@98195e0aef221aa82c47bb632324127745469f2e LESSONS.md:86`).
It costs no new computation: `composeInput` already emits
`groups: [{ name, cotag, members }]`.

**AC2 — the pin's carrier is the CLAIMS ARTIFACT, which becomes a typed record.**
Given a `cotags` invocation carrying `--claims`,
when the claims file is a bare `{group: claim}` map,
then it is **refused by name** — as §12.1 v9 refuses the withdrawn bare array — and the
conformant shape is:

```json
{
  "composition_pin": { "tag": "<T>", "pin": "<survey record pin>",
                       "groups": { "<T> × architecture": ["lesson:…"] } },
  "claims": { "<T> × architecture": "…" }
}
```

*Amended by §11 v10.* v9 required the pin to "accompany" the claims and never said where
it lives — an unnamed deferral. One artifact carries claim and provenance together,
because a pin in a separate file can go stale beside the claims it accompanies and
nothing in the tool would catch it. The declined `--composition-pin` flag permits exactly
that separation.

**AC3 — the refusal is bound by CONTENT, not by presence.**
Given claims accompanied by a valid composition pin,
when the claims' group/member set is **not a subset** of the member set the pin covers,
then `cotags` refuses with the offending members **named** — which is what AC1's
correction from a digest to the served set exists to make possible.
This is the load-bearing criterion. A pin asserting only that `compose-input` *ran* is
satisfiable by a session that runs it, takes the pin, and composes from the whole survey
anyway — existence evidence standing in for standing
(`consulted: product-lab@98195e0aef221aa82c47bb632324127745469f2e LESSONS.md:63`).
The subset relation is what makes composing outside the bounded read **unproducible**
rather than discouraged.

**AC4 — the pin binds the survey record it was computed against.**
Given a composition pin computed against one survey record,
when it is presented with a different record,
then `cotags` refuses rather than silently re-resolving. A stale pin must not become a
confident wrong acceptance.

**AC5 — `SKILL.md` composes the new field.**
Given `.claude/skills/terrain/SKILL.md` is the producer of this input (sites at `:59`,
`:70`, `:144`, `:159`, and the hard line at `:195`),
when the format gains the pin,
then the skill's instructions carry it, and the hard line at `:195` names the mechanism
that now enforces it rather than standing alone as prose.

**AC6 — the existing `cotags` fixture block covers both directions.**
Given `checks/check-terrain-composition.sh`'s `cotags` fixture block already has a home
for this,
when the change lands,
then fixtures assert **both** the conformant path (a subset composition is accepted) and
the refusal (a member outside the bounded read is rejected, named). A fixture that only
demonstrates acceptance does not discharge this item.

**AC7 — `compose-input`'s existing bounded-read fixture is preserved.**
Given `checks/fixtures/terrain/compose-input/stub-gateway.mjs` and the bounded-read
fixture already in that check,
when the emitter changes,
then that fixture still passes or is updated deliberately with the change recorded — not
silently rewritten to match new output.

## The three obligations §11 v10 attaches

This is a **second** breaking format change to a composed input, after §12.1 v9's typed
subdivision record, so the implementing sitting owes all three:

1. a **boundary fixture in both directions** — a conformant typed record accepted, and a
   non-subset refused **with the offending members named**;
2. the **bare-map refusal by name**, matching how §12.1 v9 refuses the withdrawn bare
   array, so a stale composer fails loudly rather than silently;
3. a **measured** count of existing claims artifacts this breaks, or a stated zero. An
   unmeasured format break is the class `LESSONS.md:45` names, and a zero is a result
   rather than an excuse to skip the count.
