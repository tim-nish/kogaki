## Story

As the owner reading a co-tag screen or a Full Report in a terminal, I want the
Group and SubGroup a line belongs to to survive line wrapping, and I want the
substrate pin to appear once instead of once per member — so that the hierarchy
is still legible where the claim text is longest, and so that the report shows
me the material rather than repeating its address.

## Grounding

- **Governing contract:** `specs/spec-terrain/SPEC.md` §6.1 v6 and §6.2 v6 (the
  hierarchy carrier), §12 v12 (the served-line map and pin-once), all amended

## Acceptance criteria

**AC1 — the Group ID is minted once and matches its registered shape.**
Given `cmdCotags` composing the group list,
when the screen is emitted,
then every group carries a `GroupID` matching `^G[0-9]+$`, unique within the
screen, assigned over the composed groups in `COTAG_SORT` order — and no other
command assigns one.

**AC2 — the SubGroup ID names its parent.**
Given a group `G<n>` with SubGroups,
when they render,
then each carries a `SubGroupID` matching `^G[0-9]+-[0-9]+$` whose prefix is
its parent's GroupID, so the parent is readable from the ID without a lookup.

**AC3 — no line on the co-tag screen encodes its level in leading whitespace.**
Given each of `terrain/terrain.mjs:777`, `:790`, `:794`, `:821`, `:823`,
when the surface renders,
then the line begins at column 0 and its level is carried by its ID. This is
the criterion the whole story exists for: a re-introduced indent is a
re-introduced defect, and `report-format.json`'s
`cotag_screen.indentation_is_not_a_carrier` states it as contract.

**AC4 — the Full Report uses the same IDs.**
Given `renderReportMarkdown`,
when a group or SubGroup heading renders,
then it carries the same `G<n>` / `G<n>-<m>` the screen showed for that run, so
an owner copying an ID from the screen can find it in the report.

**AC5 — the substrate pin renders exactly once per file.**
Given a Full Report rendering,
when every line carrying a pin is counted,
then the count is 1, and it is the identity block's `*Substrate pin:*` line.
Asserted by COUNTING OCCURRENCES over the rendered bytes, not by the registered
`pin_once_per_file` rule — that rule counts the `substrate_pin` line class and
read 1 against a specimen carrying six, which is the gap §12 v12 records.

**AC6 — the served-line map survives, sited once, with bare rows.**
Given the trailing `## Served lines` block,
when it renders,
then it is present (§12 requires it), sited at the report's end, and each row
carries `file:line` with no `@<pin>`. The Gloss cite rows are bare on the same
grounds. Removing the map is NOT this story's option — §12 v12 decided that
fork and kept it.

**AC7 — the golden specimens are regenerated and still asserted twice.**
Given `checks/fixtures/terrain/format/`,
when the suite runs,
then both specimens carry the new form, each still conformant against the
grammar AND byte-equal to the renderer's output. A specimen edited to match a
renderer that violates the grammar is the failure mode; §14.5's precedence is
one-way and the check reports the SPECIMEN stale.

**AC8 — an existing conformant run still emits.**
Given a survey record and claims that produced a conformant screen and report
before this story,
when the same invocation is repeated after it,
then the run succeeds and the emit-time refusal fires on nothing. A refusal on
the happy path means the grammar and the emitters disagree, which is what
story 1.54's guard exists to surface.

**AC9 — `line_class_allowlist` is LIVE again on the co-tag screen.**
Given `report-format.json` v3's `group_prose` form `> <composer prose>`,
when `cmdCotags` emits connective prose,
then the line carries the `> ` marker — and a line no class admits is REFUSED,
which is the rule working again rather than reading as enforced while
`group_prose` swallows everything. Owner decision 2026-08-11 (SQ4).
**Assert the rule FIRES**, not merely that the marker renders: a crafted
unadmitted line must be refused on this surface. A marker with the rule still
inert would satisfy the letter and none of the point.

**AC10 — the refusal block's crafted test strings are updated with the forms.**
Given `checks/check-terrain-composition.sh`'s emit-time-refusal block,
when the grammar carries the v3 flush-left forms,
then its five crafted nonconformant strings are re-authored against those
forms. They are v2-shaped today, which is why the suite is red on the spec diff
alone — a case of the fixture encoding the shape it was written beside.

**AC11 — the G/SG ID is assigned in sort order and its scope is stated.**
Given `cmdCotags` minting GroupIDs over the composed group list,
when the ids are assigned,
then they follow `COTAG_SORT` order, and the surface or its documentation
states plainly that **a pin advance may renumber them** — the id is valid for
the run that printed it. Owner decision 2026-08-11 (SQ1), mirroring story
1.53's answer for `L` ids: no persistent map is written, which AC3 forbids
anyway, and the screen and report of one run agree, which is what kogaki#314's
owner-entered id set needs. A printed screen from a previous pin does not, and
saying so is part of the criterion.

## Story questions

- **SQ1 — ANSWERED 2026-08-11 by the owner on kogaki#317; the deferred slot is
  filled and its criterion is AC11.** Kept here as the record of what was asked
  and what was chosen, per the decide-or-name rule that required it.
- **SQ2 — does the screen show a group's ID when it has no SubGroups?** AC1
  mints an ID for every group unconditionally, which is the simple reading.
  Whether a flat group's ID earns its screen space, or reads as noise beside a
  co-tag name that already identifies it, is a presentation judgment §6.1 v6
  does not settle. Raise it if the rendering looks wrong in hand.
- **SQ4 — ANSWERED 2026-08-11 by the owner on kogaki#317: give composer prose a
  marker.** `report-format.json` v3 carries `group_prose` as `> <composer
  prose>`; the criterion is AC9 as amended. Kept here as the record of the
  question. The original framing follows.

  *How does composer prose become decidable again?* Removing the
  indentation removed the only constraint on `group_prose`, so the allowlist
  went inert on this surface (recorded at
  `cotag_screen.line_class_allowlist_went_inert_here_in_v3`). Two shapes, and
  the sitting that found this **declined to pick between them mid-execution**
  because both are presentation decisions on the surface kogaki#317 had just
  ruled on: (a) give composer prose a rendered marker — a leading `> ` or `· `
  — so it is distinguishable without carrying level; (b) declare the rule
  inapplicable to this surface and say why, as `full_report` already does.
  (a) keeps a live guard at the cost of one more glyph the owner did not ask
  for; (b) is honest and gives up a check that was working through v2. Raise it
  with alternatives; do not settle it in code.
- **SQ3 — `cmdSubdivide`'s own rendering (`:1315`, `:1317`) is a DIFFERENT
  surface from the co-tag screen**, and `report-format.json` covers only
  `cotag_screen` and `full_report`. Bringing it under the grammar is §14.1's
  own reopen trigger and is explicitly **not** this story's work; rendering it
  consistently by hand is. Say which you did.

## Review Focus

- **AC5 is asserted by counting occurrences, deliberately.** The registered
  `pin_once_per_file` rule counts a line CLASS and passed against six pins;
  reusing it here would reproduce the defect the story is fixing.
- **AC7's two-sided assertion is the one that catches a lazy fix.** Editing the
  specimens to match whatever the renderer now emits satisfies half of it and
  fails the other half, because the specimen is also validated against the
  grammar.
- **SQ1 is a deferred slot with a named home.** It is not licensed to be
  settled in the implementation, unlike story 1.53's analogous question — the
  blast radius is larger and the IDs are owner-copied.
- **`format-guard.mjs` should need no edit.** If it does, the grammar is not
  carrying the form and something has been hard-coded that should not be.
