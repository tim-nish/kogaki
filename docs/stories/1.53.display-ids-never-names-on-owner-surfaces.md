## Story

As the owner reading a co-tag screen or a Full Report, I want members named by a
short ID that means the same thing on every surface, so that I read information
that can be explicitly justified instead of ~40-character slugs the machine
wants to display — and so that a Brief launched from plain IDs still resolves to
served members and pins.

## Grounding

- **Governing contract:** `specs/spec-terrain/SPEC.md` §14.3 (v14) — no owner
  surface renders an element name; the rendered token is `display_id`, assigned
  **once** in the survey record, which **is** the ID→slug map.
- **Where the id is minted today**, `terrain/terrain.mjs:300`:
  `lessons.push({ id: \`lesson:${rec.slug}\`, slug: rec.slug, family: "lesson", tags: rec.tags || [], cite: line.cite, journey: null })`
  — read, not inferred. `display_id` is added beside these fields.
- **Owner surfaces rendering a slug today** (each read):
  - `terrain/terrain.mjs:471` — candidate rows print `c.id` (`lesson:<slug>`).
  - `terrain/terrain.mjs:719` — SubGroup header prints `sg.members.join(", ")`.
  - `terrain/terrain.mjs:842` — claim member pins print `p.id`.
  - `terrain/terrain.mjs:993` — adopt prints `adopted.members.join(", ")`.
  - `terrain/terrain.mjs:1177` — subdivide prints each `sg.members` id.
  - `terrain/terrain.mjs:1731` `memberBlock` — the Full Report member heading
    is `#### \`${id}\``, with `*Served line:*` beneath at `:1736`.
- **The machine record keeps the slug**, `specs/spec-terrain/SPEC.md:2918`
  §12.2 (v11): *"The machine record keeps everything §12.1 says … A record is
  machine-facing and the run workspace is its legitimate home."*
- **Why once rather than per artifact:**
  `consulted: product-lab@4cc496b39be1d7641aaaaf678668fb64eda35f17 topics/knowledge-architecture.md:50`
  — *"two vocabularies do not merely disagree, they make the join return
  NOTHING, which reads as no data rather than as a conflict."*
- **`L1, L2, L3` had no carrier.** No `L<n>` identifier existed in this
  repository before v14 — searched `specs/spec-terrain/SPEC.md`,
  `specs/spec-draft-pipeline/SPEC.md` and `terrain/terrain.mjs`. §14.3 mints the
  space; this story implements the mint.

## Acceptance criteria

**AC1 — the field exists in the schema.**
Given `specs/spec-terrain/survey-schema.json`,
when a candidate record is validated,
then `display_id` is present and matches `^L[0-9]+$`.

**AC2 — assigned once, at survey time.**
Given `cmdSurvey` composing candidates (`terrain/terrain.mjs:281`, mint at
`:300`),
when the survey record is written,
then every candidate carries a `display_id` unique within the record, and no
other command assigns one.

**AC3 — the record is the map, and there is no second carrier.**
Given a `display_id` on any owner surface,
when it is resolved,
then the resolution reads the survey record's candidate entry for `slug`,
`cite` and `id` — and no per-artifact map is written by `cmdCotags`,
`cmdReport`, `cmdClaim`, `cmdAdopt` or `cmdSubdivide`.

**AC4 — no element name reaches an owner surface.**
Given each of `terrain/terrain.mjs:471`, `:719`, `:842`, `:993`, `:1177`,
`:1731`,
when the surface renders a member,
then it prints the `display_id` and **zero** `lesson:` tokens and zero slugs.
This covers Lesson names, Journey names and Decision names per kogaki#318.

**AC5 — the Full Report member heading loses its second name-shaped row.**
Given `memberBlock` (`terrain/terrain.mjs:1731`) renders `#### \`lesson:<slug>\``
with `*Served line:* \`<cite>\`` beneath (`:1736`),
when it renders under this story,
then the heading is the plain `display_id`. **Whether the `*Served line:*` row
survives is SQ2 below** — kogaki#318 calls them "two name-shaped rows where the
owner ruled one plain ID suffices", which is a reading of the pair, not an
instruction about the cite.

**AC6 — the machine record is unchanged in what it keeps.**
Given the survey record and the report JSON,
when inspected after this story,
then both still carry slugs, cites and the full identity triple — §12.2 v11's
split is honored, not narrowed.

**AC7 — a member with no `display_id` is an ABNORMAL condition, marked and
never substituted.**
Given a legacy survey record written before this story,
when an owner surface renders from it,
then the surface states the abnormality explicitly and substitutes nothing —
the same discipline `specs/spec-terrain/SPEC.md:1607` §9 applies to a missing
Gloss rendering (`terrain/terrain.mjs:486`), reused rather than re-derived.
Falling back to the slug would reintroduce exactly what this story removes.

## Story questions

- **SQ1 — renumbering across a pin advance.** §14.3 states the ID is stable
  *within* a pin and that a pin advance may renumber. Whether assignment is
  corpus-order-stable (so a pin advance that adds one Lesson does not shuffle
  every ID) is **not decided** by §14.3 and is not asserted here. Decide in
  implementation; a shuffling assignment is legal under the contract but hostile
  to an owner holding a printed screen.
- **SQ2 — does `*Served line:*` survive in `memberBlock`?** A cite is not an
  element name, so §14.3 does not remove it; kogaki#318's specimen text counts
  it as one of "two name-shaped rows". **Cannot-determine from the issue** —
  raise it as a question before the edit rather than deciding it in code.
- **SQ3 — legacy survey records.** Run-workspace artifacts are uncommitted and
  regenerable (`specs/spec-terrain/SPEC.md:2918` §12.2 v11), so regeneration is
  the expected answer rather than a migration. Not asserted as a criterion
  because the regeneration cost was not measured.
