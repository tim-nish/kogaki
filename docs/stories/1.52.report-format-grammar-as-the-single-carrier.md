## Story

As the maintainer of the terrain surfaces, I want the rendered format's rules to
live in one machine-readable artifact that wins against this spec's prose, so
that a format decision lands as a grammar edit instead of as a ninth
amendment-layered prose site nobody re-derives the same way twice.

## Grounding

- **Governing contract:** `specs/spec-terrain/SPEC.md` §14.1 (v14) — the
  grammar is the single carrier of the **rendered form**, and where prose and
  grammar disagree about it, the grammar wins.
- **The prose sites being governed** (read, not inferred):
  `specs/spec-terrain/SPEC.md` §6.1 `:735`, §6.2 `:863`, §9 `:1607`, §12 `:2330`,
  §12.1 `:2390`, §12.2 `:2844`, the STRUCK section `:2879`, §12.2 (v11) `:2918`.
  Line numbers are pre-amendment and shift by the v14 status block; the section
  headings are the stable anchor.
- **§9's screen-1 allowlist**, `specs/spec-terrain/SPEC.md:1607`: *"Screen 1's
  tag rows carry a declared ALLOWLIST, and a line class not on it does not
  render … Permitted on a tag row: the tag name, and the tag's Lesson count."*
  This is the one allowlist already stated in prose and is what the grammar
  transcribes first.
- **Emitters that will consume it** (story 1.54, not this one):
  `terrain/terrain.mjs:574` `cmdCotags`, `terrain/terrain.mjs:1788` `cmdReport`.

## Acceptance criteria

**AC1 — the artifact exists and is self-describing.**
Given a maintainer opening `specs/spec-terrain/report-format.json`,
when they read it,
then it declares, per owner surface (`cotag_screen`, `full_report`), the
admissible **line classes**, the **token shape** of each field, and the
surface's **allowlist**, and a line class outside the allowlist is declared
**refused** rather than admitted.

**AC2 — §9's stated allowlist is transcribed, not reinterpreted.**
Given the grammar's `cotag_screen` tag-row entry,
when compared against `specs/spec-terrain/SPEC.md:1607`,
then it permits exactly the tag name and the tag's Lesson count, and nothing
else — the prose's own enumeration, carried across verbatim in meaning.

**AC3 — the decidable set from §14.2 is expressible.**
Given `specs/spec-terrain/SPEC.md` §14.2's enumeration (pin occurrences per
file == 1; zero `lesson:` tokens and zero element names on an owner surface;
G/SG ID grammar present; member lists carry display IDs; sum(SubGroup members)
== parent count; catch-all ≤ 30%; line class outside the allowlist ⇒ refuse),
when each is checked against the grammar's vocabulary,
then every one is expressible in the artifact — or the artifact carries an
explicit `not_expressible` entry naming which and why. A silently unexpressed
rule is the defect this story exists to remove.

**AC4 — the grammar governs the rendered form and nothing else.**
Given a reviewer asking whether the grammar decides member placement, claim
wording, figure honesty, or §2.1's family-naming duty,
when they read the artifact,
then it declares its own scope as the rendered form only, matching §14.1's
"What precedence does NOT reach" paragraph.

**AC5 — the spec's prose points rather than restates.**
Given `specs/spec-terrain/SPEC.md` §14.1 already declaring precedence,
when this story lands,
then no *new* format rule is added to SPEC.md, and the eight existing prose
sites are left unedited — governed by precedence, per §14.1's stated reason.

**AC6 — the token shape for a member is `^L[0-9]+$`, and the transition is
declared.**
Given story 1.53 has not yet landed and the emitters still render
`lesson:<slug>`,
when this story writes the member-position token shape,
then it is `^L[0-9]+$` per §14.3, **and** the artifact carries an explicit
`pending_producer: "story 1.53"` marker on that entry, so the interval in which
the grammar is stricter than the emitters is declared rather than discovered by
story 1.54's first run.

## Story questions

- **SQ1.** Line grammar or JSON Schema? §14.1 names the file and its duties and
  deliberately does not decide the encoding. A schema is checkable by existing
  tooling; a line grammar expresses per-line classes more directly. Decide in
  implementation and record the reason in the artifact — this is an encoding
  choice inside a decided contract, not a deferred fork.
- **SQ2.** Does `checks/check-registry-conformance.sh` need a row for the new
  artifact? `checks/registry.json` exists (`checks/registry.json`) and its
  contract was not read for this story — **cannot-determine**, not an assertion
  of either answer.
