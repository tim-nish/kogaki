Umbrella: https://github.com/tim-nish/kogaki/issues/66. On conflict, the
umbrella issue and `specs/SPEC.md` §4 ("Consult evidence is sided", the
tool-emits-the-receipt clause) win.

As the Kogaki repository owner, I want the tool that performed a consultation to
print the complete receipt block itself, so that the receipt stops being a
transcription exercise and the kogaki#32 vocabulary-coining class becomes
unproducible rather than merely detected.

## Context

`specs/SPEC.md` §4's tool-emits-the-receipt clause is this story's governing
text, added under kogaki#66's alternative A. Two shipped defects are the
evidence and both are transcription defects: kogaki#32 (a hand-transcribed
receipt minted an outcome vocabulary the hub never served, while the ratified
triple sat in the transcribing session's own context) and kogaki#75 (a
`request_id` copied across two receipts with the outcome reversed — the defect
the cross-receipt reuse check at `checks/check-consult-receipts.sh:219-238` now
catches after the fact).

**This is a new capability, not a modification of an existing one.**
`policy/kit/bin/gateway-query.mjs` is 152 lines and contains no
receipt-composition code — no `receipt`, `request_id`, `outcome` or `consulted`
identifier appears in the file. It spawns the gateway, prints the tool result's
text, and exits (`writeThenExit`, `policy/kit/bin/gateway-query.mjs:41`); its
usage line is `--consumer <name> --tool <tool> --args '<json>'`
(`policy/kit/bin/gateway-query.mjs:3`).

**`checks/check-consult-receipts.sh` is deliberately UNCHANGED.** It validates
shape — the continuation grammar at `checks/check-consult-receipts.sh:69`, the
ratified-triple test at `:84`, the cross-receipt reuse test at `:219-238` — and
shape does not move when the producer does. The check keeps its job for the
marked-exception path.

**The `outcome` token is NOT settled by this story.** `specs/SPEC.md` §4 names
`deferred-slot: consult-outcome-token-assignment` and leaves it open; who
assigns the token is a decision act owed on kogaki#66. This story implements the
half that does not depend on it — the fields the transport *observed* — and
story 1.21 carries the half that does. See AC 4.

## Acceptance criteria

1. **Given** a consult performed through the kit's transport, **when**
   `gateway-query.mjs` is invoked in receipt mode, **then** it prints, in
   addition to the tool result it prints today, a complete v2 receipt block in
   the grammar `specs/SPEC.md` §4 fixes: line one `consulted: <repo>@<sha>
   <file:line…>`, then indented `request_id:`, `outcome:` and one `query:` line
   **per framing actually run**.

2. **Given** two framings were run in one receipt-mode session, **when** the
   block is emitted, **then** it carries two `query:` lines, verbatim as sent —
   not the last one only. `checks/check-consult-receipts.sh:166,172` already
   fails an `uncovered-after-N-framings` whose N disagrees with the query count,
   so an emitter that dropped framings would produce a block its own repository
   rejects.

3. **Given** the gateway is unreachable, **when** receipt mode is requested,
   **then** the existing degradation contract is unchanged: one
   `policy_source unavailable: <reason>` line and exit 11
   (`policy/kit/bin/gateway-query.mjs:53-56`). A degraded run emits **no**
   receipt block, because a receipt for a consult that did not happen is the
   fabrication the clause exists to prevent.

4. **Given** the `outcome` token, **when** this story is implemented, **then**
   the emitter does **not** silently choose an assignment strategy: it emits the
   fields it observed (`request_id`, every `query:`) and takes the token from an
   explicit caller-supplied value, failing rather than guessing when none is
   supplied. Filling `deferred-slot: consult-outcome-token-assignment` — whether
   the tool may assign the token itself — is a decision act owed on kogaki#66
   before any code embeds a choice, per `specs/SPEC.md` §4's deferred-slot
   clause. **This criterion is a refusal, not a fill.**

5. **Given** a consult performed outside the kit's transport (the MCP tools
   called directly, or a degraded environment), **when** the receipt is composed
   by hand, **then** it remains admissible and is **marked** as the exception in
   a fixed, greppable form, so that the exception rate is countable rather than
   inferred. The marker is validated by the same shape check, which needs no new
   judgment clause to do it.

6. **Given** the emitted block is quoted as an example — in `SKILL.md`, in a
   template, in this story — **when** `checks/check-consult-receipts.sh` reads
   it, **then** it is inside a fenced block and read as a mention rather than a
   use (`.claude/skills/consult-first/SKILL.md:68-69`). A receipt emitter whose
   own documentation trips the checker is the use-vs-mention defect (kogaki#41)
   re-introduced.

## Blast radius

- `policy/kit/bin/gateway-query.mjs` — the new receipt path.
- `.claude/skills/consult-first/SKILL.md` (70 lines) — the receipt grammar at
  `:45-69` stops being an instruction to hand-compose and becomes a routing
  instruction plus the marked-exception path.
- `policy/kit/templates/` — `policy/CAPABILITIES.md` is **kit-managed** (its
  first line is the `tsurezure-client-kit:file (managed — replaced by
  install.sh …)` marker), so any consumer-facing text changes in the template,
  never in the installed file.
- `policy/kit/test/install-test.sh` (130 lines) — gains coverage for the new
  mode.
- `checks/check-consult-receipts.sh` — **unchanged, deliberately.**

## Story questions

- *Which surface carries the marked-exception token, and what is it?* AC 5 fixes
  the property (fixed, greppable, countable) and not the spelling; the spelling
  is a shape decision inside the grammar this repository owns. Recorded as a
  question rather than a criterion because the shape check's exact tolerance for
  a new indented key was not read this sitting —
  **unverified: `checks/check-consult-receipts.sh`'s handling of an unrecognised
  continuation key was not established.**
