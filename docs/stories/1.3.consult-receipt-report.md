As the Kogaki repository owner, I want the consult-first discipline to have a
reading act, so that consultations stop being invisible — three ran during
the kogaki#2/#3 sittings and nothing surfaced them.

## Context

The issue's sketch asked for counts "verified against the gateway access
log". That was refuted at triage: the access log is the **server's** record
and Kogaki's `consulted:` lines are the **consumer's**
(`consulted: product-lab@bb68ccf topics/archive/knowledge-architecture.md:271`
— "served mode = server-side access log is the canonical record …, consumer
`consulted:` lines remain as their own receipts; logging lives with whichever
component mediates access"). The log is also machine-local
(`~/.tsurezure/access.jsonl`, `tsurezure-gateway/src/log.ts:79-91`), so no CI
step can read it. `specs/SPEC.md` §4 now carries the sided-evidence clause
this story implements against.

## Acceptance criteria

- **Given** a branch whose commits or PR body carry `consulted:` receipt
  lines, **when** the gate runs, **then** it reports the count and the
  distinct pins seen. (New behavior.)
- **Given** a branch with no receipts, **when** the gate runs, **then** it
  reports **zero explicitly** — never silence. An obligation generates no
  event to hook, so the whole remedy is making the absence observable
  (`consulted: product-lab@93e4730 gloss/lessons/agents.md:101`, cited in
  `commands/ship-cycle.md`'s own auto_merge premise).
- **Given** any branch state, **when** the gate runs, **then** it **never
  fails on the count** — this is a report, not a gate. It may fail only on a
  malformed receipt (a `consulted:` line whose pin is not
  `<repo>@<sha> <file:line>` shaped).
- The check reads only git-resident text (commits, PR body). It never reads
  `~/.tsurezure/` or any gateway state — the boundary
  `specs/SPEC.md` §4's sided-evidence clause and
  `policy/consultation-map.md` entry 2 both name.
- Registered in `checks/registry.json` with a complete admission record:
  contract carried, license `kogaki#7`, tier, measured runtime, and a
  removal signal declared at birth
  (`consulted: product-lab@bb68ccf topics/claude-code-ops.md:19`).

## Story questions

- Whether the report surfaces in the `checks` workflow's existing job or its
  own is the implementer's call; the acceptance criteria bind the output,
  not the job layout.
- Whether a receipt on a *merge* commit counts toward its branch is
  undecided — cannot-determine, no served position consulted on it. Treat
  the first implementation's choice as provisional and state it in the PR.
