Umbrella: https://github.com/tim-nish/kogaki/issues/334. On conflict, the
umbrella issue and `specs/spec-client-kit/SPEC.md` §3.1 and §3.4 win.

As a sitting that is about to make a policy decision, I want the shape read
refreshed and its delta shown before I start, and I want every zero in the digest
to carry the denominator it was counted against, so that a stale pin is visible
rather than silently trusted and an empty section can be told from a failed read.

## Context

The contract was written in the same sitting that files this: §3.4 (host decided,
carrier state marked) and §3.1 (the denominator clause) of
`specs/spec-client-kit/SPEC.md`, decided as alternative A of the coupled
#320 / #334 selection. **This story implements those; it decides nothing.**

Three facts read before writing:

- **§3.4's act had no invoking carrier.** `policy/kit/bin/shape.mjs` ships
  `--out`/`--stdout`; nothing regenerates, diffs pins, or surfaces a delta.
  §3.4 now names the host — a kit step invoked by `commands/spec-sitting.md` —
  and declares `instrument: none` with a reopen trigger until both land.
- **The per-term drop is real and silent.** `shape.mjs`'s per-term loop does
  `if (e.soft) continue;`, so a term whose `glossary_entry` read could not be
  parsed is indistinguishable from one with no state line.
- **The element-level three-state rendering already exists** — rows, `None of
  N`, `Could not establish` — from PR #335. This story extends that discipline
  from elements to terms; it does not invent it.

**Accepted file overlap with story 1.50, stated rather than discovered**
(`specs/spec-triage-gh/SPEC.md` §"Decomposition considers file boundaries"):
both touch `policy/kit/test/install-test.sh` and
`specs/spec-client-kit/SPEC.md`. Irremovable by a different cut — two umbrella
issues, and the story↔issue binding is 1:1. A **scheduling edge only**: never
`depends_on`, never a GitHub dependency link.

## Acceptance criteria

**1 — The delta step exists as a kit command.**
Given a vendored `policy/shape.md` with a pin,
when `policy/kit/bin/shape.mjs --delta` runs,
then it regenerates live, compares the vendored pin against the served pin, and
reports the policy delta between them.

**2 — The delta renders through the owner-register path, not as a receipt.**
Given the delta output,
when it reaches the screen,
then it carries no `consulted:`, no `request_id:` and no `@<sha>` —
`specs/spec-client-kit/SPEC.md` §8 governs it, because a delta shown before a
sitting is an owner surface.

**3 — `commands/spec-sitting.md` invokes it as a pre-step.**
Given a spec sitting,
when it starts,
then the delta step has run and its output precedes the sitting's first act;
and the sitting's record carries the shape pin it ran under (§3.4).

**4 — It reports and never gates.**
Given a stale pin, an unreachable gateway, or no vendored digest at all,
when the pre-step runs,
then the sitting proceeds — nothing is withheld. A step that blocked a sitting
fails this criterion; §3.5's enhancer-never-dependency property forbids it.

**5 — Every zero carries its denominator, per element AND per term.**
Given a digest render,
when any section is empty,
then it states what it was counted against (`of N read`);
and a term whose own read could not be parsed is **counted and named**, never
skipped — the per-term case §3.1 now binds.

**6 — Both directions are fixtured.**
Given the rendering fixtures,
when they run,
then a dropped-term case fails if the term vanishes silently, and a
genuinely-empty case fails if it is reported as a dropped read. One direction
alone passes while the collapse runs the other way — the fixture blind spot PR
#332 round 2 was earned by.

**7 — The install test covers the delta step.**
Given `policy/kit/test/install-test.sh`,
when it runs,
then it asserts `--delta`'s presence, its pin-free output, its non-gating
behaviour on a stale pin, and its one-line exit-11 degrade.

## Story questions (not criteria)

- **Whether the pre-step belongs in every lane command or only `spec-sitting`.**
  Unverified — §3.4 names `commands/spec-sitting.md` and says nothing about other
  lanes, and widening it would be the enumeration shape this repository refuses
  elsewhere.
- **What the delta's granularity should be** — pin-to-pin, or per changed
  headline. `cannot-determine`: §3.4 binds "present the policy delta" and does
  not fix its resolution.
