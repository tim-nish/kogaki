umbrella issue and `specs/SPEC.md` §4 win.

As the Kogaki repository owner, I want a matched consultation-map boundary
with zero receipts to **fail at the merge layer**, so that the map binds on
every PR instead of firing only when an agent's initiative fires.

## Context

`specs/SPEC.md` §4's PR-gate clause is this story's governing text, as amended
for kogaki#25, together with the issue-checkpoints clause for the pickup half.

The dependency on 1.9 and 1.10 is real, not stylistic. The check computes over
the map's declared trigger terms, whose entry schema 1.9 restructures; and it
counts receipts, whose grammar 1.10 changes. Built first, it would bind
against two shapes about to move.

Siting is the typed loop's mechanical half. The served position that governs
it:

> an obligation cannot be gated at all and needs its absence made visible

`consulted: product-lab@ed47fbd3818b9a66954a558d6c88e86574407ece LESSONS.md:87`

This check **conforms** to that rather than violating it: a PR is an event, so
receipt-absence over a diff is a computable fact rather than an absence with
nothing to hook — the same two-layer form §4 already ratifies, where "whether
a PR CONTAINS an unlicensed check is a computable fact carried at the merge
layer" (`topics/knowledge-architecture.md:36@ed47fbd`).

**This is a new registered check, not an edit to the existing one.**
`checks/check-consult-receipts.sh:2` declares itself "A REPORT, never a gate
on the count", and its registry admission record says the same. This check
gates a *different* property — matched boundary ⇒ receipt present — so it
earns its own admission record and its own removal signal rather than
falsifying one already on the record.

The pickup half already has a carrier: `policy/kit/bin/issue-pins.mjs`
`--recheck`, which is kogaki-owned. The **authoring** half of kogaki#25 §3 is
not implementable here — `~/.claude/tools/story-sync` resolves to
`/home/tomoya/work/claude-toolkit/tools/story-sync` — and is escalated to
`tim-nish/claude-toolkit`; this story covers the pickup checkpoint only.

## Acceptance criteria

- **Given** a branch, **when** the check runs, **then** it computes the set of
  consultation-map boundaries whose trigger terms match the diff paths,
  changed text, or linked issue body, **and** the set of receipts present, and
  a matched boundary with zero receipts **fails** (`specs/SPEC.md` §4, PR-gate
  clause).
- **Given** a receipt carrying **any** of the three ratified outcome tokens —
  `discriminating`, `covered-after-reframing`, or
  `uncovered-after-N-framings` — **when** the check evaluates a matched
  boundary it covers, **then** the check **passes**. The obligation is to ask
  and never to have found, so the outcome is irrelevant to satisfaction and
  the check reads only the receipt's **presence** (`specs/SPEC.md` §4, as
  corrected for kogaki#32).
- **Given** the outcome token, **when** the check runs, **then** it does not
  branch on it at all — a check that passed on some outcomes and failed on
  others would be judging whether the consultation *succeeded*, which is the
  review lane's, not the merge layer's.
- **Given** a matched boundary, **when** this check finds a receipt covering
  it, **then** it binds **presence, not order**: it asserts that a
  consultation was recorded on the branch, and asserts nothing about *when*
  it happened relative to the work. A receipt written after the code it was
  supposed to precede satisfies this check exactly as one written before it.
  Nothing in this repository observes that ordering — not this check, not the
  read prescription, not the review lane — and the gap is stated here so a
  later reader does not assume the binding covers it. (Observed live: the
  story-1.10 branch ran consultation-map entry 1's read prescription *after*
  writing the check it governs, and the receipt it emitted is indistinguishable
  from one emitted before.)
- **Given** the receipt format chosen at kogaki#28 — line one unchanged from
  v1, with `request_id`, `outcome` and `query:` on indented continuation
  lines — **when** this check looks for a receipt, **then** it reads **line
  one only**. Presence is decidable from the `consulted:` line alone, so this
  check needs no continuation-line parsing and stays independent of the
  block's internals: a later amendment to what rides inside the block cannot
  break the boundary binding.
- **Given** a matched boundary, **when** the check evaluates it, **then** it
  makes **no judgment** about whether the right question was asked — that
  stays in the review lane, and a clause admitting it here would be the
  judgment-in-the-mechanical-half defect (`specs/SPEC.md` §4).
- **Given** the new check file, **when** it is registered in
  `checks/registry.json`, **then** its admission record names the contract it
  uniquely carries, its licensing issue (kogaki#25), its tier and runtime, and
  a **removal signal declared at birth** (`specs/SPEC.md` §4, check-registry
  clause).
- **Given** the existing `consult-receipts` check, **when** this story
  completes, **then** it still reports and never gates on the count — its
  contract is not absorbed, redefined, or deleted by the new check.
- **Given** fixtures under `checks/fixtures/`, **when** the suite runs, **then**
  both discriminating cases are exercised: a matched boundary with a receipt
  (passes) and a matched boundary with none (fails) — a gate whose failing
  path is never fired is the orphan-guard shape kogaki#6 was filed to end.
- **Given** an issue body carrying `consult: deferred-to-pickup`, **when**
  `policy/kit/bin/issue-pins.mjs --recheck` runs at pickup, **then** the
  deferred consultation is enforced there and refuses with the delta if
  undischarged (`specs/SPEC.md` §4, issue-checkpoints clause).

## Story questions (unverified — not acceptance criteria)

- What "changed text" the trigger-term match should read — commit messages,
  the diff body, the PR body, or all three — is **unverified**: the existing
  receipt check reads commit messages plus `CONSULT_PR_BODY`
  (`checks/check-consult-receipts.sh:38-44`), and whether the boundary match
  should share that source set is a design call for implementation, not an
  inference from the neighbouring check.
- Whether a false-positive trigger match (a boundary term appearing
  incidentally in a diff) is tolerable at gate severity is **open**. The map's
  own ratified accretion polarity — an entry that turns out not to apply
  costs one consultation, never a false verdict — was argued for an
  *advisory* map; at gate severity the cost of a spurious match is a blocked
  merge instead. Raise it at implementation rather than deciding it silently.
