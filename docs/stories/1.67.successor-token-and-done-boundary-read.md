# Story 1.67: The successor token, and the done-boundary read that reports its survivors

## Context

Canonical discussion record: **kogaki#461**. On conflict, the issue wins.

`specs/SPEC.md` §4 clause 13 (written 2026-08-15, owner selection on #461)
rules that an issue discharged by a sibling's merge declares the relation as a
**token at the close**, and that the `done` boundary **reports** the survivors.
This story builds the reading half.

The defect it closes: an issue split out of a parent to carry "the remainder"
can be discharged by that parent's own successor PR, and no read notices.
kogaki#403 carried the fix half of kogaki#269; PR #406 merged licensed by #269
and implemented #403's entire scope; #403 sat open for two days asserting an
absence that was false.

**The polarity is fixed by the clause and is not this story's to revisit.** The
defect is an absence, so nothing here gates, denies, or closes.

## Scope

One file carries the change, and the spec is already amended — this story does
not touch `specs/SPEC.md`.

- **`checks/check-review-report.sh`** — the `done` boundary already computes the
  set of issues **this merge closes** and cross-references declaration lines
  against it (`:474-475`, `:598-626`, the evaporating-carrier rule). This story
  adds one reading over that same set.

## Acceptance criteria

1. **AC1 — the token is parsed, anchored, and strict.** A closing comment line
   of the form `successor: #<n>  <scope text>` declares the relation. Anchored
   whole; one declaration per line; the scope text is **required and
   non-empty**; a malformed line declares **nothing** rather than declaring a
   relation with an empty scope. This mirrors clause 10's `supersedes:` grammar
   discipline (`specs/SPEC.md` §4 clause 10), which is cited rather than
   re-derived.

2. **AC2 — the survivors are reported at the `done` boundary.** For a merge
   whose closed-issue set is computed at `checks/check-review-report.sh:598-626`,
   any **OPEN** issue carrying a `successor:` declaration that names an issue in
   that set is reported, with its number and its declared scope text.

3. **AC3 — reported, never gated.** The reading adds no `unmet` row that can
   turn the gate red, withholds no merge, and closes nothing. §4 clause 13 fixes
   this polarity and §4 clause 12 already holds it for the sibling obligations;
   a build that gates has implemented a different clause.

4. **AC4 — an empty reading renders.** A merge whose closed-issue set has no
   declaring survivors says so explicitly. Silence is not a reading: a run that
   printed nothing would be indistinguishable from one where the read never ran,
   which is the disclosure discipline this file already owes elsewhere.

5. **AC5 — the prospective bound is stated where it is read, not only in the
   spec.** Issues closed before the token existed declare nothing, so a zero is
   the token's absence and not a clean sweep. The output says which.

## Verification

**AC1, AC2 and AC4 are mechanically checkable and owe a mutation, not an
observation.** Fixture cases over crafted bodies: a well-formed declaration
naming a closed-by-this-merge issue is reported; one naming an unrelated issue
is not; a malformed line (missing scope text) declares nothing; an empty set
renders its explicit zero. Then **break the read** and confirm the assertions
fail — a case that passes when nothing is read is the defect class kogaki#243
tracks, and story 1.66's round 1 showed a mutant can also fail for the wrong
reason, so **each mutant asserts it RAN before any absence is read**
(PR #465 round 1, finding 1).

**AC3 is a polarity property and is asserted by construction plus a case**: the
reported row must not appear in whatever set the exit status is computed from,
and a fixture whose only finding is a declaring survivor must exit **zero**.

## Out of scope

- **Fixing `_successor_from_closing_comment`.** That reader lives in
  `~/.claude/tools/story-sync` (claude-toolkit) and resolves **#269 → #269**
  today. It is a real defect and it is **escalated, not repaired here** — this
  repository cannot change it, and clause 13 deliberately depends on neither its
  behaviour nor its grammar.
- **Backfill.** Clause 13 is prospective by ruling; no historical close is
  amended.
- **Any close, any gate.** The clause reports. `/repo-cleanup`'s
  never-auto-close discipline is untouched.
- **Arm (b)'s coverage** — an issue whose work landed with no declared relation
  at all stays invisible. Declined on #461 with grounds; not a gap in this story.
