Umbrella: https://github.com/tim-nish/kogaki/issues/325. On conflict, the
umbrella issue and `specs/spec-client-kit/SPEC.md` §3 win.

As the owner of a kit-installed repository, I want every session to load a
pinned, scoped digest of the served policy surface without my initiating
anything, and I want a spec sitting to show me the policy delta since that pin
before it starts, so that a design discussion is grounded from the moment the
kit is adopted rather than running unglossed until its first registered
boundary — the moment redesign is most expensive.

## Context

The contract for this story was written in the same sitting that files it:
`specs/spec-client-kit/SPEC.md` §3 (v1), decided as alternative A of the
coupled #325 / #326 selection. **This story implements that section; it decides
nothing.** Where this body and §3 differ, §3 wins.

Three facts about the shipped code this story changes, each read before
writing:

- **The transport and the served reads already exist.** `policy/CAPABILITIES.md:12-20`
  enumerates seven read-only tools; `gloss_index`, `lessons_index`,
  `glossary_entry` and `surface_names` are the four the digest composes over,
  and `policy/kit/bin/gateway-query.mjs` is the transport that reaches them.
  **No `shape` tool exists and none is added** — §3.2.
- **The install script manages five artifacts today**, at
  `policy/kit/install.sh:59-113`: the `CLAUDE.md` block, `policy/consultation-map.md`,
  `policy/CAPABILITIES.md`, `policy/source.yaml`, and
  `.claude/skills/consult-first/SKILL.md`. The digest is a sixth, and the
  script is idempotent by contract.
- **`.gitignore` already carries the exactly parallel precedent.** The
  `reports/` entry names §2.5.2 and states the reasoning verbatim — repo-visible
  so the owner reads it where they work, not committed because it inherits its
  sources' sensitivity. `policy/shape.md` is the second member of that class,
  and its comment says so rather than restating the argument.

**Accepted file overlap with story 1.49, stated rather than discovered**
(`specs/spec-triage-gh/SPEC.md` §"Decomposition considers file boundaries"):
both stories touch `policy/kit/install.sh`,
`policy/kit/templates/claude-md-block.md` and `policy/kit/test/install-test.sh`.
The overlap could not be removed by a different cut, because the two clauses
are bound to two separate umbrella issues and the story↔issue binding is 1:1.
It is a **scheduling edge only** — never written to `depends_on`, never a
GitHub dependency link — and the implementing lane serializes on it.

## Acceptance criteria

**1 — The composer exists and touches no gateway surface.**
Given a configured gateway and a declared consumer,
when `policy/kit/bin/shape.mjs --consumer <name>` runs,
then it composes the digest from `gloss_index`, `lessons_index`,
`glossary_entry` and `surface_names` through `policy/kit/bin/gateway-query.mjs`,
and no request is made to any tool absent from `policy/CAPABILITIES.md:12-20`.

**2 — The digest carries all five elements, and renders an empty one explicitly.**
Given a successful composition,
when the digest is written,
then it carries tier-1 gloss headlines scoped to the consumer, glossary state
lines for terms in scope, the consumer's role-assigned obligations, one line per
`policy/consultation-map.md` boundary, and its pin plus generation date;
and any element with no members renders as an explicit empty statement rather
than being omitted — §7 question 1 is open on *scoping*, not on whether the zero
is rendered.

**3 — The digest is repo-visible and NOT committed.**
Given a kit install into a repository,
when the install completes,
then `policy/shape.md` exists in the working tree and `.gitignore` excludes it,
with a comment naming `specs/spec-client-kit/SPEC.md` §3.3 and `specs/SPEC.md`
§2.5.2 — the second decision made explicitly, per §2.5.2, rather than by where
the file landed.

**4 — The managed block references it, and the reference is the carrier.**
Given `policy/kit/templates/claude-md-block.md`,
when the kit installs or refreshes,
then the managed block carries one paragraph pointing at `policy/shape.md` and
stating that a grounded answer displays the headline verbatim with its pointer,
separately from the session's own narrative;
and the clause appears **in the managed block**, not only in
`.claude/skills/consult-first/SKILL.md` — `specs/spec-client-kit/SPEC.md` §2
refuses skill-as-sole-carrier.

**5 — Refresh is a sitting pre-step that reports a delta and gates nothing.**
Given a vendored digest whose pin is behind the served pin,
when the spec-sitting pre-step runs,
then it regenerates live, presents the policy delta before the sitting starts,
and the sitting's record carries the shape pin it ran under;
and a stale pin **withholds no work** — §3.5, and the enhancer-never-dependency
property inherited at §1.

**6 — Degradation is honest and non-fatal.**
Given an unreachable gateway,
when `shape.mjs` runs,
then it prints exactly one `policy_source unavailable: <reason>` line and exits
11, matching the contract at `policy/kit/README.md:38-42`, and an install
containing it still completes — a degraded install is a valid install.

**7 — The install-test fixture covers the new artifact.**
Given `policy/kit/test/install-test.sh`,
when it runs,
then it asserts the digest's presence, its `.gitignore` entry, the managed-block
reference, and the degraded path — the same three properties the existing
managed artifacts are asserted on.

## Story questions (not criteria)

- **What a consumer with zero `projects:` matches receives** — an empty digest
  or the unscoped tier-1 index. Carried as `specs/spec-client-kit/SPEC.md` §7
  question 1; **cannot-determine** until decided, so it is a question here and
  not a criterion. Criterion 2 binds only that the zero is rendered.
- **Whether the spec-sitting pre-step belongs in `commands/spec-sitting.md` or
  in a kit-provided step the command invokes.** Unverified — the placement was
  not settled at the selection, and §3.4 binds the *act*, not its host.
