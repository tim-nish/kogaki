## Story

As the operator running Terrain's co-tag view,
I want a Full Report to record the judge that produced its outcome **whether or not
that outcome had a leaf split**, and the subdivision input to *state* judged-emptiness
rather than imply it from an empty list's truthiness,
so that a group whose judgment ran and found no split is distinguishable in the
artifact from a run that never judged — which is the conformant/non-conformant
boundary §12.1 v8 draws and the runtime currently cannot express.

## Context — what the code actually does

Measured at `kogaki@96b6776`. The defect is larger than "judged-empty is emitted with
`none`": the runtime **cannot emit the conformant artifact at all**, by three
composing mechanisms.

- `subOf(g)` returns `subdivisions[g.name]`, and `[]` is truthy in JavaScript, so
  `{"Group": []}` already takes the judge-required branch (`terrain/terrain.mjs:1405`,
  `:1429`). Judged-empty is *accidentally* expressible, by a language property nothing
  states.
- On that branch `subgroupPlacement(group, [], …)` places nothing, computes `unplaced`
  as **every member**, and pushes the `no_member_hidden_subgroup` catch-all
  (`terrain/terrain.mjs:1011-1020`) — so the artifact carries **one** SubGroup holding
  the whole membership, not zero.
- `members: subgroups ? null : renderMembers(group.members)` (`terrain/terrain.mjs:1484`)
  then nulls `members`, because `[]` is truthy there too.

Key absent, `{}` and `[]` therefore yield three different conformance outcomes and
none is the conformant one.

## Acceptance criteria

**AC1 — the judge pin is required unconditionally.**
Given any `report` invocation on the co-tag path,
when it runs,
then `--judge-model` and `--judge-effort` are **required** regardless of whether any
target group carries SubGroupClaims, and `judgePin` is the supplied judge — `NO_JUDGE`
is never minted (`terrain/terrain.mjs:1429`).

**AC2 — `--subdivisions` takes a typed per-group record.**
Given the subdivision input,
when a group's entry is `{"judged": true, "subgroups": [...]}` it is judged with a leaf
split; when it is `{"judged": true, "subgroups": []}` it is **judged, empty**; when the
key is absent the group is not judged and the co-tag path refuses,
then judged-empty is stated in the input rather than inferred from truthiness.

**AC3 — a judged-but-empty group emits the conformant artifact.**
Given a group whose judgment ran and produced no leaf split,
when its report is generated,
then it carries its judge pin and **zero** SubGroupClaims, the
`no_member_hidden_subgroup` catch-all does **not** fire, and `members` stays
**populated** rather than `null`.

**AC4 — the artifact distinguishes judged-empty from never-judged.**
Given two reports, one from a judged-empty group and one from a run that never judged,
when they are compared,
then they are distinguishable in the artifact, per §12.1 v8's two-state statement.

**AC5 — `NO_JUDGE` stays in the identity/schema layer.**
Given §12.1's uniform arity,
when this change lands,
then `NO_JUDGE` remains valid and typed in the identity triple, `(pin, query, none)`
stays constructible by a requester who does not hold the report, and reports minted
under it before the amendment still resolve. Nothing is deleted from the key space.

**AC6 — `cmdCotags` follows in the same change.**
Given `cmdCotags` reads the same subdivision map (`terrain/terrain.mjs:614-628`),
when the input format changes,
then that reader is migrated in the same PR. A fix that migrates one reader and not the
other rebuilds the defect between them.

**AC7 — an executable conformance fixture sits at the producer/consumer boundary.**
Given the producer is `.claude/skills/terrain/SKILL.md` (which composes the subdivision
input) and the consumer is `cmdReport`,
when the format changes,
then `checks/check-terrain-composition.sh` carries a fixture asserting the **typed**
form end to end, including the judged-empty case.
Required by the amendment rather than suggested by it —
`consulted: product-lab@98195e0aef221aa82c47bb632324127745469f2e LESSONS.md:45`:
*"because producer and consumer hold separate suites over one contract, neither side
can see the break, so the contract owes an executable conformance fixture at the
boundary."*

**AC8 — §8's no-member-count-threshold rule is untouched.**
Given §6.2's *"No member-count threshold is introduced or implied"*,
when this change lands,
then nothing introduces a floor on members. A reading of this story that supplies one
is a misreading, refused in advance.
