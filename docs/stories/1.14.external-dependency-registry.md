Umbrella: https://github.com/tim-nish/kogaki/issues/55. On conflict, the
umbrella issue and `specs/spec-external-deps/SPEC.md` win.

As the Kogaki repository owner, I want the capabilities this repository needs
but cannot install to be declared and read at run time, so that an unmet one
fails as itself rather than presenting as a stall or as a grant that was never
exercisable.

## Context

`specs/spec-external-deps/SPEC.md` (v1, kogaki#55) is this story's governing
text, authored in the same sitting under alternative A. `specs/SPEC.md:69`
carries the founding-spec bullet that sites the registry beside the check
registry (`specs/SPEC.md:64`) and the gate registry.

The specimen is the held run on PR #51: three obstacles — the spawned
reviewer's tool grants, the repository's `allow_auto_merge`, the merge deny's
install state — were **one defect**, all assumed and none declared.

**What this story delivers is the carrier, not its content.** The spec sitting
wrote the contract (`specs/spec-external-deps/SPEC.md`) and the machine-readable
field lists (`specs/spec-external-deps/deps-schema.json`); neither the
enumeration nor the check that reads it exists. This story writes both, which
is why it is not born-satisfied by the sitting that authored it.

**The check reads the schema rather than restating it.** That arrangement is
already the house pattern — `specs/spec-gate-carrier/SPEC.md:53` states it for
`checks/check-gate-carrier.sh`, and `specs/spec-gate-carrier/gate-schema.json`
records the same reasoning in its own note: one carrier, so amending the
contract is one edit and never a two-copy divergence.

## Acceptance criteria

1. **Given** `deps/registry.json` does not exist, **when** this story lands,
   **then** it exists and declares at least the three capabilities kogaki#55
   named — the repository's `allow_auto_merge` setting, the merge-eligibility
   PreToolUse deny's install state, and the spawned session's tool grants —
   each carrying every field
   `specs/spec-external-deps/deps-schema.json`'s `entry.required` list names.

2. **Given** an entry whose presence is decidable by a cheap read, **when** the
   check runs, **then** that read is executed and its result rendered, present
   or absent. The `allow_auto_merge` entry's read is a `gh api` call against the
   repository; the PreToolUse deny's is a presence read over the actor-level
   settings file that `~/.claude/tools/story-sync install-hooks` writes.

3. **Given** an entry whose presence has no cheap read, **when** the check
   runs, **then** its `verification.reason` is rendered as its own row rather
   than omitted — per `specs/spec-external-deps/SPEC.md` §3, a typed
   `none: <why>` is evidence and an omission is not.

4. **Given** a decidable verification reports the capability **absent**,
   **when** the check runs, **then** the check **still passes** and the absence
   is reported. It fails only on a malformed or incomplete entry. This is the
   `never_fails_on` list in `specs/spec-external-deps/deps-schema.json`, and it
   mirrors the split `checks/registry.json`'s `consult-receipts` admission
   already records for its own check: "Fails only on a malformed receipt, never
   on the count."

5. **Given** an act depends on a capability the registry does not declare,
   **when** that absence is observed, **then** it is surfaced **report-only
   with its reason** and never silently admitted — the non-member fallback of
   `specs/spec-external-deps/SPEC.md` §4, which is the load-bearing half of the
   enumeration.

6. **Given** the registry is empty, **when** the check runs, **then** the zero
   is rendered explicitly rather than passing silently. The precedent is
   `specs/spec-gate-carrier/SPEC.md:50-52`, where the gate registry's own empty
   state is rendered for the same reason: a silent pass is indistinguishable
   from a check that did not run.

7. **Given** the check exists as a file, **when** the suite runs, **then** it is
   registered in `checks/registry.json` with a complete admission record —
   contract, licensing issue (`kogaki#55`), `tier`, `runtime_ms`, and a
   `removal_signal` declared at birth — because the registry's own note
   (`checks/registry.json:2-7`) makes an unregistered check file dead code
   found by `check-registry-conformance.sh`.

8. **Given** the check's own logic, **when** it runs, **then** it exercises an
   embedded fixture pass over conformant and malformed entries, so the
   discrimination is evidence rather than assertion. This is the shape every
   sibling check in `checks/registry.json` already carries.

## Story questions

- **Which tier?** `pre-push` matches every current sibling, but
  `check-client-kit-install.sh` already costs 6336ms in that loop
  (`checks/registry.json`). The `gh api` read in criterion 2 adds network
  latency to a pre-push hook. **Unverified — the loop budget's current total
  was not measured this sitting.** Measure it at implementation and record the
  measured `runtime_ms`; if the network read makes pre-push unacceptable, the
  decidable reads move to the CI tier and the conformance half stays pre-push,
  which is a split the schema's `check_semantics` already permits.

- **Does the route log carry the report, or only stdout?**
  `specs/spec-external-deps/SPEC.md` §5 names "a run's preflight" as the second
  consumer and points at the review sweep's route log. **Unverified —
  implementation not located:** no preflight read of any dependency registry
  exists in `tools/review-sweep.sh` today. Whether this story wires that second
  consumer or leaves it to kogaki#60's spawn work is a scoping question for the
  implementer, not a criterion here.

## File boundaries

Touches `deps/registry.json` (new), `checks/check-external-deps.sh` (new), and
`checks/registry.json` (one entry). **Accepted overlap:** kogaki#60's story
adds its grant-list entry to `deps/registry.json`. Sequenced, never a
`depends_on` on that side — the overlap is a scheduling edge.
