Issue: https://github.com/tim-nish/kogaki/issues/60. On conflict, the issue
and `specs/SPEC.md` §4 win.

As the Kogaki repository owner, I want every spawned session to carry its own
declared tool grants and to say so when it exits without its artifact, so that
a permission wall stops being an invisible stall and becomes a fact on the PR.

## Context

`specs/SPEC.md:152` is the governing text and it is already written: the PR
gate's **orchestration** — spawn on PR-open, rally rounds, author-session
messaging — lives in the lane-command layer. This story is orchestration work
under an existing invariant, which is why it is a story rather than a spec
amendment.

**The defect is measured, not predicted.** PR #58 delivered the model pin, the
turn cap, and per-round route logs, and the route logs immediately showed both
live reviewers running to completion **blocked on tool permissions** (94 and 37
stream events). Until the grants ride the spawn, no autonomous round can
complete and every spawned reviewer ends report-less at the wall.

`tools/review-sweep.sh:268-271` is the site: the `cmd` list carries `--model`,
`--max-turns`, `--verbose` and `--output-format`, and **no `--allowedTools`**.
There are two call sites through one helper — the reviewer and the fixer
(`tools/review-sweep.sh:464`) — and `spawn`'s signature
(`tools/review-sweep.sh:253`) already takes a per-call `model` override, which
is the shape a per-call grant list follows.

**`depends_on: 1.14` is real, not stylistic.** Criterion 5 registers the grant
list into `deps/registry.json`, which story 1.14 creates. Making the
registration conditional on that file existing would leave a promise nothing
collects — the defect class kogaki#29 was filed over.

**Why the stall comment must not be a report.** `specs/SPEC.md:112` (§4 clause
1) makes the mechanical half read **report present ∧ no open blocking
findings**. A stall notice shaped like a report would satisfy presence while
carrying no review, which inverts the gate. The fixer prompt already applies
the same discipline from the other direction —
`tools/review-sweep.sh:243` instructs the fixer never to post a
`review-lane report:` comment — so this story extends an existing rule to a new
emitter rather than inventing one.

## Acceptance criteria

1. **Given** a reviewer session is spawned, **when** the command line is built,
   **then** it carries an explicit `--allowedTools` list scoped to the review
   lane's needs — `gh` reads plus `gh pr comment`, `bash checks/*.sh`, the
   `mcp__tsurezure__*` seam tools, and file reads — and **never**
   `--dangerously-skip-permissions`. The repository is public and the
   user-level merge deny must stay meaningful.

2. **Given** a fixer session is spawned, **when** its command line is built,
   **then** it carries its **own, narrower** list — edit, commit and push, and
   **no `gh pr comment`**. The fixer is already barred from posting reports
   (`tools/review-sweep.sh:243`), and after kogaki#56 its comment would count
   toward the trusted-author set.

3. **Given** the two lists differ, **when** they are declared, **then** they
   are declared **beside the model pin and overridable in the same way** —
   `spawn(prompt, log_path, model=None)` at `tools/review-sweep.sh:253` is the
   existing per-call override shape, and `FIX_MODEL`
   (`tools/review-sweep.sh:213`) is the existing per-role knob. Two places that
   both know a default is two places that can disagree about it, which
   `tools/review-sweep.sh:209-213` already records as the reason the fixer's
   model is resolved once in the shell.

4. **Given** a spawned session exits without its expected artifact — permission
   wall, max-turns, or crash — **when** the sweep observes that exit, **then**
   it posts a plain PR comment naming the reason, in a form that **cannot**
   match the `review-lane report:` presence token of `specs/SPEC.md:112`. The
   reason appears where the failing check already is.

5. **Given** `deps/registry.json` exists (story 1.14), **when** this story
   lands, **then** the spawned session's tool grants are registered there as an
   entry carrying the fields
   `specs/spec-external-deps/deps-schema.json`'s `entry.required` list names —
   the grant list is precisely "a capability the repo needs but cannot install".

6. **Given** the grant lists are declared, **when** the sweep runs in
   `--dry-run` mode, **then** the preview names them, on the same ground the
   dry run already names the model and the cap
   (`tools/review-sweep.sh:478-481`): a preview that withheld the one thing the
   run turns on would leave the operator reading the source for it.

## Story questions

- **Does the stall comment need its own idempotency guard?** A sweep re-run
  against an unchanged head would post a second identical comment.
  **Unverified — implementation not located:** no comment-deduplication exists
  in `tools/review-sweep.sh` today, since the tool has posted no comments until
  now. Whether to key on head sha, or to accept repetition as the honest signal
  that the wall is still there, is an implementer's call to raise rather than a
  criterion here.

- **What exactly is "its expected artifact" for the fixer?** The reviewer's is
  a `review-lane report:` comment; the fixer's is a push, observed today only
  through the exit code (`tools/review-sweep.sh:465-470`). **Cannot-determine —
  the fixer's success condition is not recorded anywhere consulted this
  sitting.** Criterion 4 is written against "exits without its expected
  artifact" deliberately, and the fixer's instance of that phrase is a question
  the implementation answers.

## File boundaries

Touches `tools/review-sweep.sh` and `deps/registry.json`. **Accepted overlap,
both stated:** story 1.16 also edits `tools/review-sweep.sh`'s spawn path, and
story 1.14 creates `deps/registry.json`. Both are scheduling edges; only the
1.14 dependency is real enough to be a `depends_on`.
