## Story

As the maintainer of `policy/kit/bin/issue-pins.mjs`,
I want each regression fixture to **fail when its fix is reverted**,
so that a green `38/38` line and a green `client-kit-install` mean the three
regressions are actually protected against reintroduction, rather than reporting
coverage the fixtures cannot deliver.

## Context — what the measurement established

The four fixes shipped by kogaki#203 (PR for kogaki#188) are **correct**; this is
not a report of a shipped bug. The finding is one level up: three of the four
fixtures placed over them watch a place the defect cannot occur, so the guard is
dead while the surface says it is live.

The mutation test was reproduced against `kogaki@bbfa614` in a scratch copy
(`git archive`; the repository itself was not modified), each fix reverted **in
isolation** to its exact pre-fix form from `git show 4b21f90 -- policy/kit/bin/issue-pins.mjs`,
with `node issue-pins.mjs --self-test` run on each mutant. Only the `parseCites`
pin-quote strip mutant fails; the other three mutants pass `38/38`.

The issue records the per-mutant table in full — it is the authority for which
three are dead, and this story does not restate it.

## Acceptance criteria

**AC1 — the exit-11 predicate is extracted and asserted discriminatingly.**
Given the exit-11 decision currently computed inline from the `judgeContent` results,
when it is extracted as a pure function (input: those results; output: whether the
run exits 11 and with what count),
then fixtures assert it directly **and fail** when the predicate is reverted to the
tally form.

**AC2 — the `prov` computation is extracted and round-tripped.**
Given `--emit-pin-quotes` computes `prov` inline,
when it is extracted as a pure function and asserted directly,
then at least one **real `--emit-pin-quotes` output line** is round-tripped through
`parsePinQuotes`, including the unparsed-pin case that produced the bare `@`.

**AC3 — `contentPass`'s file-scoping is covered.**
Given an unhashed body,
when `contentPass` runs,
then the empty file-selection result is asserted — either by extracting the
file-selection as a pure function over `(cites, quotes)`, or by an injected fetcher
the fixture can observe.

**AC4 — every new or amended fixture is mutation-verified.**
Given each fixture added or amended by this story,
when its corresponding fix is reverted,
then `--self-test` **fails**, and the mutation and its result are recorded in the PR.
A fixture whose only demonstrated failure mode is total absence of the code does not
discharge its item.

**AC5 — the placement rule is re-cut positively.**
Given `policy/kit/README.md`'s `pin-quote:` placement rule, which today names only the
indented failure,
when it is re-cut,
then it states the rule positively — **below the whole `consulted:` block, never
between line one and its continuations** — covering the unindented-inside case too.

## Story question — not an acceptance criterion

The issue's sixth item is a **fork**, stated as an either/or, and it decides input
grammar rather than restating a settled one:

> `parsePinQuotes` and `pinScanBody` are anchored consistently (`^[ \t]*pin-quote:`),
> **or** an indented `pin-quote:` is refused by name

Anchoring both to `^[ \t]*` **accepts** an indented line; refusing by name **rejects**
it. These are different contracts for what an issue body may contain, and the issue
selects neither. It is carried here as a question rather than written as a criterion,
per the grounding rule: an unverified binding is an inference, not a contract.

Either resolution owes the fixture the issue names — the doubly-invisible indented
shape, showing its `@sha` no longer reaching the pin scan.

**Answer it before implementing**, and record the answer on issue #209.

## Out of scope — declared

- No behaviour of `--recheck`, `--emit-pin-quotes` or `--validate-body` changes. All
  four kogaki#203 fixes are correct and stay as they are; extraction for testability
  must be verified behaviour-preserving.
- `checks/check-consult-receipts.sh`'s scan is **not** widened to tolerate interleaved

  documentation of where the line goes.
- The stale `30 fixtures` count in PR #203's body is cosmetic, confined to a merged PR
  body, and is not carried here.
