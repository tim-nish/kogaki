## Story

As the owner running any Terrain surface, I want a seam call that names an
argument key `element_survey` does not declare to **refuse at the call site**,
so that a survey cannot be composed from zero candidates while exiting zero and
validating.

## Grounding

- `cmdSurvey` sends `{ kinds: [...] }`. The tool declares `kind` (**singular**)
  and `tag`. An undeclared key returns the **miss shape**, so the call yields
  zero lines and `terrain survey` writes a record with **0 candidates and exit
  code 0**.
- **The failure is invisible by construction.** The record validates, the exit
  code is zero, and §13.2 makes an empty an informative outcome — so a reader
  cannot distinguish "the corpus has nothing" from "the call asked for a key
  the seam does not know". This is why it survived: there is no symptom.
- `gatewayQuery` is the one call site shape; `cmdNeighborhood` (story 1.44)
  passes `{}` deliberately and carries a comment saying `cmdSurvey`'s call is
  the broken one. That comment comes out when this story lands.
- **A worked instance of the same class, one layer out**, from the same
  sitting: `policy_lookup` was called here with `{"query": ...}` against a
  declared `question`, and it returned a **loud validation error** rather than
  a miss. The two seams differ in what an undeclared key does, which is exactly
  why the call site cannot rely on the far end to complain.
- `policy check: no remedy-shape conflict` — verdict on #368, which quotes the
  served constrain-over-detect position verbatim.

## Acceptance criteria

**AC1 — the address check runs on the QUERY path.** Given a plain
`--tool/--args` call naming a key the served tool does not declare, when it is
made, then it refuses with the same message the receipt path already produces,
naming the offending key and the declared set. It does not return a miss shape
and does not exit zero.

**AC1a — one check, not two.** Given the query path and the receipt path, when
both refuse, then they refuse **through the same function**. A second
implementation for the second path is the defect this story is about,
reproduced in the repair — a control correct in one place and absent in
another.

**AC2 — the declared set stays SERVED, never copied.** Given the argument sets,
when a call is checked, then the declaration is read from the served
`tools/list` on the same wire, as `assertAddressEvidenced` already does. No
local enumeration of tool arguments is introduced anywhere. **SQ2 is answered
and closed by this criterion.**

**AC2a — the receipt path's behaviour is UNCHANGED.** Given a receipt-composing
call, when the routing lands, then its refusals and its successes are exactly
as before. The check is being reached from one more place, not altered.

**AC3 — `cmdSurvey` composes a non-empty survey against the live corpus.**
Given the served corpus, when `terrain survey` runs, then the record it writes
carries candidates. **The proof is a run, not a fixture** — a fixture asserting
the call shape would have passed throughout the defect's life.

**AC4 — the audit is DONE and recorded; the criterion is that it stays true.**
The four `terrain/terrain.mjs` call sites were audited at re-cut and the table
is on #368: line 345 `element_survey {kinds}` is the one defective site; 516
and 1612 (`gloss_index {tag}`) and 2925 (`element_survey {}`) are clean. Given
the routing lands, when the suite runs, then **no call site sends an undeclared
key** — which the routed check now enforces rather than an audit asserting it.

**AC5 — a zero-candidate survey is distinguishable from a corpus with
nothing.** Given a composition that yields no candidates, when it completes,
then the outcome states which of the two it is. This is AC1's guarantee made
observable at the surface rather than only at the call.

**AC6 — every property has a fixture that fires.** Given AC1, AC2 and AC5, when
the suite runs, then each has a case that fails without the implementation.
AC3 and AC4 are discharged by a run and an audit respectively, and say so.

## Story questions

- **SQ1 — the content check owes admission economics, and this story does not
  grant it.** The issue asks for "a check on what the survey actually
  contains". That half is **detection-shaped**, and the served line names the
  tell: a check suite growing roughly one member per incident. It is
  defensible here, because free composition at the seam boundary is what
  remains irreducible once the helper lands — but admission is judged at the
  decision point on the declared four (defect class ended, tier, measured
  runtime, **removal signal declared at birth**), and a check that needs the
  live seam is one CI may not be able to run. **Raise it as a decision; do not
  add a registry member without one.**
- **SQ2 is ANSWERED and needs no decision.** The declaration is read from the
  served `tools/list` on the same wire the call goes out on, so a schema and a
  call cannot drift apart. The kit already does this. Do not reopen it, and do
  not add a local copy "for speed".
- **SQ3 (new) — does anything else reach the seam without the check?** The
  query path is the one this story routes. Whether another entry point into
  the kit exists that composes an argument object and bypasses both paths is
  not established here; if the implementing sitting finds one, that is a
  finding to report, not scope to absorb.

## Files this story is predicted to touch

`policy/kit/bin/gateway-query.mjs` — **the kit, licensed for this story by the
owner decision of 2026-08-12** and by nothing else. `terrain/terrain.mjs` to
correct line 345's `kinds` and to drop `cmdNeighborhood`'s comment saying
`cmdSurvey`'s call is the broken one. A check file if AC6 needs one.

**Out of licence and unchanged:** anything else in `policy/kit/`. The kit
separates into its own repository when a second consumer installs it
(kogaki#9), so a change here is a change to a component with a different
visibility future — the routing and nothing beside it.

## Review Focus

- **AC3 is the criterion a fixture cannot discharge.** The defect lived through
  a full check suite; only a run against the live corpus shows it. Check that
  the evidence offered is a run.
- **AC1a is the one this repair is most likely to fail.** The tempting shape is
  a second key-check at the query path's own entry, which reproduces this
  story's subject inside the fix for it. One function, reached twice.
- **AC2a needs asserting, not assuming.** The check currently reads state
  assembled for receipt composition (`observed`, `declared`, `catalogue`); the
  query path may not assemble all of it. If reaching the check requires
  changing what it reads, that is a change to the receipt path too and it must
  be shown not to alter its verdicts.
- **SQ1 is the criterion most likely to be stepped around** by quietly adding a
  registry member because it seems obviously good.
- **Watch for the remedy collapsing to a rename.** Correcting `kinds` to `kind`
  makes the symptom vanish and satisfies AC3 while leaving AC1 undone — the
  individual-prohibition shape #368's verdict declined by name. The rename is
  *also* owed, but as cleanup after the routing, never instead of it.
