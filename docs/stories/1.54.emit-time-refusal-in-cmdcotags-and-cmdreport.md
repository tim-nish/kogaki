## Story

As the maintainer of the terrain surfaces, I want the emitters to validate their
rendered text against the grammar and refuse to write or print on failure, so
that a nonconformant artifact is **unmintable** rather than detectable one
incident later by a check suite that has been growing at roughly one member per
round.

## Grounding

- **Governing contract:** `specs/spec-terrain/SPEC.md` §14.2 (v14) — refusal at
  the emitters, generation-time, with the check suite demoted to the fast path
  beneath it.
- **The emitters** (read, not inferred): `terrain/terrain.mjs:574` `cmdCotags`,
  `terrain/terrain.mjs:1788` `cmdReport`. The report's write path announces at
  `terrain/terrain.mjs:1636` (owner rendering) and `:1642` (machine record).
- **The precedent this reuses rather than re-derives:**
  `specs/spec-terrain/SPEC.md:1607` §9 — *"`terrain/terrain.mjs` already
  recomputes `by_family` from the placements the figure claims to be counted
  over, and refuses to write a record whose stored figure disagrees
  (`FIGURE_MISMATCH`, `terrain/terrain.mjs:206-209,278,292`) … the refusal
  stays generation-time: constrain generation, then detect what generation
  cannot promise."*
- **The grammar it validates against:** `specs/spec-terrain/report-format.json`
  (story 1.52).
- **The gap this closes**, from kogaki#319: `checks/check-terrain-composition.sh`
  validates survey JSON against `specs/spec-terrain/survey-schema.json` — the
  records have a schema and a check; the Markdown rendering and the screen text
  have neither.
- `consulted: product-lab@4cc496b39be1d7641aaaaf678668fb64eda35f17 gloss/lessons/architecture.md:249`
  — *"restrict what the system can produce in the first place … which removes
  the possibility instead of catching it."*

## Acceptance criteria

**AC1 — the screen refuses.**
Given `cmdCotags` (`terrain/terrain.mjs:574`) has composed its rendered text,
when that text violates `specs/spec-terrain/report-format.json`'s
`cotag_screen` grammar,
then nothing is printed to the owner surface and the command exits non-zero,
naming the violated line class and the offending line.

**AC2 — the report refuses before either artifact exists.**
Given `cmdReport` (`terrain/terrain.mjs:1788`),
when the rendered Markdown violates the `full_report` grammar,
then **neither** the owner rendering nor the machine record is written — the
refusal precedes both writes, because §12.2 v11 requires both to be written in
the same act and a record without its rendering reproduces the 2026-08-06
defect specimen from the other side.

**AC3 — validation is over the rendered text, not the model behind it.**
Given a defect that is invisible in the data structure but present in the
output — the pre-#234 renderer dropping four of six member fields is the
recorded specimen — when the emitter validates,
then it validates the **string it is about to emit**, which is what made every
prior §12.1 assertion stay green while the rendering dropped its material.

**AC4 — the refusal message is actionable.**
Given a refusal,
when the maintainer reads it,
then it names the surface, the line class, the offending line and the grammar
entry violated — sufficient to fix without re-deriving the format from prose.

**AC5 — the fast path is demoted, not deleted.**
Given `checks/check-terrain-composition.sh` and its siblings in `checks/`,
when this story lands,
then no existing check is removed, and the suite gains no new member for a
class the refusal now makes unreachable. §14.2's demotion is a statement about
where new rules go, not a licence to delete.

**AC6 — an existing conformant run still emits.**
Given a survey record and claims that produced a conformant screen and report
before this story,
when the same invocation is repeated after it,
then the output is byte-identical and nothing is refused. A refusal that fires
on the happy path is a grammar defect, and this criterion is what catches
story 1.52's transcription errors.

## Story questions

- **SQ1.** Is there an escape hatch for a maintainer debugging a refusal — e.g.
  `--no-validate`? §14.2 does not grant one, and granting one would restore the
  admit-on-non-member fallback the allowlist shape exists to remove. Raise
  before implementing rather than adding it quietly.
- **SQ2 — answered by §14.1, and the residue named.** `cmdView`
  (`terrain/terrain.mjs:447`), `cmdClaim` (`:819`), `cmdAdopt` (`:943`) and
  `cmdSubdivide` (`:1099`) **are** owner surfaces: §14.1 defines the term as any
  text the runtime prints for the owner to read and enumerates six. What is open
  is narrower — whether **this story's refusal** should extend to them. §14.1
  states the grammar's coverage as two of six and marks the other four as
  carrying §14.3's duty with no mechanical carrier, under a reopen trigger. This
  story implements the two; extending to the other four is that trigger's work,
  not a silent widening here. Raise it if implementation makes the extension
  cheap, because the gap is stated rather than assumed away.
