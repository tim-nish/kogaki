## Story

As the operator waiting on a review round,
I want `tools/review-sweep.sh --spawn --pr <n>` to recognise that a round is already in
flight and report it rather than spawn a second session,
so that polling the tool — the only thing that reports the round's state, and therefore
the natural way to wait — does not re-fire the trigger it is being used to watch.

Measured on PR #180: three sessions completed (29, 24 and 33 turns) and the budget read
exhausted.

## Context — the premise correction this story is built on

The issue states *"there is no persisted per-round state today"*. That is **incomplete**,
and the correction is what makes this story small.

`spawn_log_path(pr, rnd)` → `LOG_DIR/pr-{pr}-round-{rnd}.log` (`tools/review-sweep.sh:1168`)
is already keyed per PR per round, and `spawn()` writes the command line into it
**before the process starts** (`tools/review-sweep.sh:1716`, `:1775-1781`) — deliberately,
so that *"a spawn that dies immediately still leaves a file saying what was attempted."*

So a durable per-round artifact already exists in exactly the window the issue describes
as empty. What it lacks is a **terminal** line: existence alone cannot separate *in
flight* from *finished*.

## Acceptance criteria

**AC1 — `spawn()` writes a terminal line on every exit path.**
Given a spawned session,
when it exits — normally, by turn cap, by isolation failure, or by signal where a
handler can run,
then a terminal line is written to its round log. `spawn()` already returns distinct
codes (e.g. `ISOLATION_FAILED`); each terminal path writes.

**AC2 — the three states are computable from the log alone.**
Given a `(pr, round)` pair,
when the spawn path evaluates it,
then it resolves to exactly one of:
*in flight* (log exists, no terminal line, mtime inside the staleness window),
*finished* (terminal line present),
*abandoned* (no terminal line, mtime outside the window — a fresh spawn is permitted).

**AC3 — the staleness window is declared in configuration, not derived.**
Given the window is a judgment,
when it is set,
then it lives beside the other spawn knobs in the shell layer (`REVIEW_LOG_DIR`,
`MODEL`, `MAX_TURNS` — `tools/review-sweep.sh:637`, `:562`, `:641`), overridable by
environment, and is **not** a magic number inside the Python heredoc.

**AC4 — the guard is sited in `spawn()`, not at its call sites.**
Given `tools/review-sweep.sh:90` — *"THE ISOLATION IS SITED IN `spawn()`, NOT AT ITS CALL
SITES"* — and the served line placing the missing component *between the instruction and
the spawn*,
when the guard is added,
then it is in `spawn()` (or a helper it alone calls), so call site N+1 is covered by
default.

**AC5 — a second invocation reports and exits 0.**
Given a round already in flight,
when `--spawn --pr <n>` is invoked again,
then it prints the PR, the round, the log path and the age, spawns nothing, and exits
**0**.
Grounds — `consulted: product-lab@98195e0aef221aa82c47bb632324127745469f2e topics/archive/knowledge-architecture.md:197`:
*"when the verdict count is zero, no gate-shaped nag may be emitted — repeatedly walking
the owner to an empty gate is exactly the channel-eroding failure."*
A poll exiting non-zero on its normal case makes *not yet done* indistinguishable from
*broken*, and the operator's repair is `|| true`, which removes the guard entirely.
**Disclosure is not traded away**: the in-flight round is printed every iteration. Only
the exit code was at issue.

**AC6 — the carrier's reader set is enumerated, not discovered.**
Given `rounds_used()`, `rally_cycles()`, `decide()`, `park_class()` and the `--recent`
path all read round state,
when this lands,
then each is listed in the PR with a statement of whether it consults the new terminal
line and why.
Grounds — `consulted: product-lab@98195e0aef221aa82c47bb632324127745469f2e LESSONS.md:43`:
*"a carrier owes an enumerated READER set rather than only a write contract … a
per-reader fix repairs one reader and leaves the count unchanged."*

**AC7 — a fixture covers the re-fire.**
Given the sweep's `FIX` fixture pass,
when a `(pr, round)` with an in-flight log is presented twice,
then the second invocation is asserted to spawn nothing and exit 0, and the abandoned
case is asserted to permit a fresh spawn.
