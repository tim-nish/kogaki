Umbrella: https://github.com/tim-nish/kogaki/issues/271. On conflict, the
umbrella issue and `specs/SPEC.md` §4 clause 10 win.

As the Kogaki repository owner, I want the sweep to **record a degraded review
in band** and to **export the per-PR disposition it already computes**, so that
a caller outside `tools/review-sweep.sh` can tell *this head is reviewed* from
*a report exists here*, and so that a report written by a denied-tools session
stops reading as `done`.

## Context

`specs/SPEC.md` §4 **clause 10** is this story's governing text, ratified for
kogaki#271. The orchestrator half of that issue — a dispatcher spawning
reviewer sessions against state it never read — is escalated to
`tim-nish/claude-toolkit#282` and is **out of this story's scope**: nothing
here binds a caller, and the clause says so.

Three facts about the shipped code this story changes:

- `decide()` (`tools/review-sweep.sh:2637`) is already a pure function
  returning `done` / `author-owes` / `park` / `spawn-round-N` for one PR at one
  head. It is reachable **only** by running the sweep, and `--dry-run` prints
  prose.
- The `report-degraded` arm (`tools/review-sweep.sh:4509-4517`) *knows* the
  session was denied tools and posts `post_stall_comment`, which is bound to no
  segment and carries no token the state machine reads. `decide()` therefore has
  **no degraded input at all**, and a head whose only report came from a denied
  session reads `done`.
- `post_stall_comment` (`tools/review-sweep.sh:2274`, whose fixed sentence is at
  `:2286`) asserts *"the gate stays red, correctly"* — **false three times**, each
  at the same head as the report it described: #249 and #254 on the 2026-08-08
  run, and **PR #293 itself**, the PR that ratified clause 10, whose round-1
  reviewer was denied tools and whose registry check went `success` at 10:01:10Z
  off the very report the notice was describing. #255 is the honest
  counter-case — its check never re-ran green — and must not be broken.

The presence-check class this repairs is served:

> nothing in the output distinguishes computed over nothing from computed and
> found nothing … The test is to ask what the function would return if its
> input were empty, unreadable, or the wrong source, and if that matches its
> normal healthy output, the check is missing and the failure is invisible by
> construction.

## Acceptance criteria

1. **The token exists and is written.** The `report-degraded` arm posts
   `review-report-degraded: <head sha>` as a PR comment line, anchored whole,
   taking the same 7–40 hex sha its siblings take, read in the same single pass
   over the same segmenter, **first declaration wins**. It rides an adjacent
   line and widens no existing token, so the regexes at
   `checks/check-review-report.sh:245` and `tools/review-sweep.sh:723` are
   unchanged.

2. **The token is read, and changes the verdict.** A PR whose current head
   carries a report from a denied-tools session resolves to a state **distinct
   from `done`**, and the sweep's embedded fixture pass asserts it — the file
   already carries fixtures for every other `decide()` arm.

3. **It never satisfies the presence token.** A fixture asserts that a
   `review-report-degraded:` line alone does not make
   `checks/check-review-report.sh` report a review present, on the same ground
   `post_stall_comment` was deliberately kept out of report form.

4. **The read is exported and three-valued.** A caller outside
   `tools/review-sweep.sh` obtains the state as a typed value in **one read**,
   as a machine-readable form of the **existing `--dry-run` path** — not a
   dedicated mode. The value set is `covered` / `needs-a-round` /
   `cannot-determine`, and `cannot-determine` is distinct from `covered`.

5. **The two paths cannot disagree.** The export evaluates the **same
   predicate** the spawn path evaluates, and the existing kogaki#227 liveness
   fixture (`tools/review-sweep.sh:3886`) covers the export as it covers
   `--dry-run`, rather than the export becoming a third path with no agreement
   fixture.

6. **The notice stops asserting a red gate.** `post_stall_comment`'s fixed
   sentence states what the notice *is* — not a review, carrying no presence
   token — and no longer asserts the gate's state, which it does not read.
   Verified against the #249 and #254 timings recorded on the umbrella issue,
   which are the specimens; #255 is the counter-case and must not be broken.

7. **A live `--dry-run` over a PR in each of the three states prints the state
   it would export**, and the run record is cited at close.

8. **The notice stops asserting an ABSENT REPORT on the path where one
   landed** (folded from kogaki#309, 2026-08-09). `post_stall_comment` has
   **one fixed body** used at **two call sites with incompatible meanings**:
   the genuine-absence site (`result != 0 or landed is False`) and the
   **partial-denial** site, in the `else` branch where a report *did* land and
   which passes `reason = "the report landed, but the session was denied tools
   and the review may be degraded"`. The body's heading — *"review-lane spawn
   produced no report"* — is false at the second site, and is contradicted by
   that reason string **inside the same comment**. The heading is derived from
   the call site that already knows which fact holds, exactly as AC 6 derives
   the gate-colour sentence.

   **AC 6 is unchanged and this does not restate it.** They are the two false
   sentences of one body: AC 6 removes the gate-state claim, AC 8 removes the
   absence claim. #309 observed both **on a green gate, twice**, in the
   2026-08-09 run — beside the #249, #254 and PR #293 specimens AC 6 already
   carries.

   The absence path's body is **unchanged**, and still cannot satisfy the
   presence token — the invariant AC 3 asserts.

   *Why the widening was right and the reuse was not:* the comment beside the
   partial-denial site records that the first form of the fallback *"fired
   only on TOTAL artifact absence"*, leaving *"a GREEN GATE OVER A SILENT
   HOLE … surviving on the partial-denial path because the trigger condition
   was narrower than the failure class it was declared to cover."* Widening
   the **trigger** was correct; reusing the **body** written for the narrow
   case was not, and nothing checked the pairing.

9. **A fixture covers both call sites' TEXT, not only their trigger
   conditions** (folded from kogaki#309). The existing fixture population
   asserts *when* each arm fires; nothing asserts *what it says*, which is
   exactly how a widened trigger reached a body written for a different case
   with no check observing it. The fixture's unit is the **rendered body per
   call site**. The denial list and the false-label warning are correct on
   both paths and stay shared.

10. **The export's contract states WHEN it must be evaluated.** A read at
   dispatch is necessary and not sufficient — kogaki#271 establishes across
   PR #275 (31 s), #277 (inside the sitting) and #282 (70 s, inside the
   sitting) that the window does not shrink in a way a fixed margin covers. The
   exported value's documentation states that a caller re-evaluates
   **immediately before the act it suppresses**, and that this changes the
   timing and not the polarity: suppression stays permitted on `covered` alone.

## Out of scope, stated rather than discovered

- **Binding any caller.** The clause gives a read; honouring it is
  out-of-repository by construction, and the clause marks that carrier-less
  with its own reopen trigger.
- **kogaki#72's blocking budget and the two-round cap.** Untouched.
- **Any soundness signal for a report's CONTENT.** #256's round 1 carried no
  degradation notice and its defect was a claim made without reading a pin. This
  story bounds waste; it does not promise to preserve every good round.
- **`cannot-determine:`'s existing reviewer-owned role** (kogaki#100) is neither
  widened nor gated.
