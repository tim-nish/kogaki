Umbrella: https://github.com/tim-nish/kogaki/issues/295. On conflict, the
umbrella issue and `specs/SPEC.md` §4 clauses 3 and 4 win.

As the Kogaki repository owner, I want `spawn()` to consume a single-use owner
grant before it creates a reviewer process, so that **no** reviewer session is
created without authorization **whatever invoked the sweep** — including the
watcher, terminal or pre-hook routes that no session-level PreToolUse carrier
can ever see.

## Context

`specs/SPEC.md` §4 **clause 3** is this story's governing text, as amended for
kogaki#295: the round bound is carried at **three** layers, and the third is the
act of process creation. §4 **clause 4** carries the mechanism — the siting rule
(`spawn()`, never its call sites) and the declared grant class.

The incident the clause records, verified at the PR: **both** reviewer sessions
for PR #293 were created by `tools/review-sweep.sh` (rounds 1 and 2, 09:56:02Z
and 10:03:36Z) while `claude-toolkit#283`'s gate — installed 09:17Z, before
either — was never invoked. No harness tool call launched the sweep in either
window.

**The uncovered route was already declared, which is what makes this a known
gap rather than a discovered one.** `~/.claude/hooks/gate-reviewer-spawn.py`'s
own docstring, under *"WHAT THIS DOES NOT COVER"*:

> Spawns from outside this user's Claude Code sessions — another machine,
> another account, CI, cron. A session hook reaches only tool calls made in
> [a session].

The approvals store this story reads is the **same store that hook consumes**,
and its shape is observable rather than inferred: `~/.claude/review-approvals/`
holding one `*.json` record per grant with `repo` / `pr` / `round`, consumed by
stamping `consumed_at` and `consumed_by`, with denials appended to
`denials.log` as JSONL.

`spawn()` (`tools/review-sweep.sh:2025`) is **shared** — the driver spawns the
fix through it (`:4331`) and the fixtures spawn noop and never-launch cases
through it — while `claude-toolkit#283`'s contract is about **reviewer**
sessions. That is why the check is keyed by class rather than applied wholesale.

The layer rule that sites the carrier here:

> When the layer where a rule's violation occurs belongs to ANOTHER SYSTEM, no
> carrier can be installed there — the carrier goes at the LAST BOUNDARY YOU
> CONTROL, and any gate upstream of it is ergonomics rather than control.

`consulted: product-lab@dec0d568dd8fc0b2df1185eac10dc1a10600f299 topics/archive/knowledge-architecture.md:158`

## Acceptance criteria

1. **`spawn()` takes a required grant class.** Every call site declares one.
   The argument is required rather than defaulted — a default is what would make
   this an enumeration of the classes someone remembered.

2. **`reviewer` consumes or refuses.** A `reviewer` spawn consumes one
   unconsumed grant matching this repository and PR from the approvals store and
   proceeds; with no matching open grant it **refuses fail-closed** and creates
   no process. An unreadable or unparseable store refuses; an already-consumed
   grant refuses.

3. **An undeclared class refuses.** A call site that passes no class is
   refused, so call site N+1 is denied by default rather than admitted. A
   fixture exercises this directly — it is the clause's load-bearing property
   and the one a future caller is most likely to erode.

4. **The fix path is not gated, and its absence of a rule is stated.** The fix
   spawn (`:4331`) declares its own class and proceeds without consuming a
   reviewer grant. The story adds no rule for it; §4 clause 4 records that it
   has none.

5. **The refusal is its own reported state.** `refused: no grant` is distinct
   from a stall in the sweep's counts and in the park/stall reporting: a spawn
   declined for want of authorization is a different fact from a session that
   started and produced nothing.

6. **The refusal is terminal and legible.** It names the missing approval,
   prints the same grant instruction the session hook prints, never retries, and
   logs the refusal.

7. **`--dry-run` consults the same predicate WITHOUT consuming it.** The dry run
   reports whether an open grant exists and leaves it open. This is kogaki#227's
   same-predicate rule where the predicate has a side effect: a prediction that
   consumed the grant it predicted on would make the preview the act. A fixture
   asserts the grant is still unconsumed after a dry run.

8. **The store is read-and-consume only.** The sweep never writes a grant. A
   fixture asserts no code path in `tools/review-sweep.sh` creates an approval
   record.

9. **Fixtures, in the file's existing embedded style:** spawn with no grant
   refuses; spawn with an open grant consumes it and proceeds; a consumed grant
   does not authorize a second spawn; an undeclared class refuses; a dry run
   leaves the grant open.

## Out of scope, stated rather than discovered

- **The hook-side halves** — the interpreter-wrapper matcher bug and
  pre-registration session population — are `tim-nish/claude-toolkit#285`. This
  story is the layer that reaches what no session hook can, and the two compose:
  whichever boundary sees the act first consumes the grant.
- **Demoting or changing the session hook.** It stays exactly as installed.
- **The round budget itself.** §4 clause 3's bound is unchanged in size; what
  changes is that a round within budget is no longer *sufficient* to spawn.
- **Granting.** The store is owner-owned; this story only reads and consumes.

## Accepted file overlap, stated per §"Decomposition considers file boundaries"

This story and **story 1.42** (issue #294, umbrella kogaki#271) both touch
`tools/review-sweep.sh`, and both touch the `--dry-run` predicate — 1.42 to
export a three-valued state from it, this story to consult a grant without
consuming it. They are **not** folded, because they sit under different
licensing issues, and the overlap is a **scheduling edge only**: it is recorded
here and never written to `depends_on`.
