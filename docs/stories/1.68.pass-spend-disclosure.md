# Story 1.68: The pass close discloses its own spend — every spawn made, every grant consumed

## Context

Canonical discussion record: **kogaki#470**. On conflict, the issue wins.

`specs/SPEC.md` §4 clause 4's addition "A PASS DISCLOSES ITS OWN SPEND"
(written 2026-08-15, owner selection at the #470 recommendation gate) rules
that each sweep pass names every spawn it made and every grant it consumed at
the pass close, **empty sets included**. This story builds it.

The defect it closes is a reading failure, not a spend failure: the spawn-log
directory and the approvals store are global while a sweep's stdout is
per-process, so two concurrent passes each print one true account and both
operators read the directory against the wrong one. In the measured specimen
(2026-08-15, PRs #468/#469), each session spent the other session's click's
sibling grant correctly, and each operator's output attributed to their own
click a round they never asked for.

**What is fixed by the clause and not this story's to revisit:** grants stay
target-keyed and requester-less; the spawn-log directory stays global (the
in-flight guard depends on it). Nothing here gates, denies, refuses, or
changes any spend semantics — the story adds disclosure only.

## Scope

One file carries the change: **`tools/review-sweep.sh`**.

- **Track at the two act sites that already exist, never derive from the
  directory.** A module-level record (e.g. `PASS_SPAWNS`, `PASS_CONSUMES`):
  - `spawn()` appends `(tag, grant_class, log basename)` at the claim write —
    the moment a spawn artifact exists in the global directory. Refusals and
    in-flight declines return before the claim and are deliberately not
    "spawns it made".
  - `consume_grant()` (the single call site) appends `(pr, round, tag)`.
- **Render at the pass close**, beside the existing
  `swept N open PR(s): …` counts line, and also at the
  `no open pull requests — nothing to sweep` exit (fixture spawns may already
  have claimed by then, and a disclosure that skips an exit path is the
  per-call-site defect this file names about itself):
  - one line naming every spawn this pass made (log basename + tag),
  - one line naming every grant this pass consumed (PR, round, tag),
  - **the empty case renders as an empty case** ("this pass spawned nothing /
    consumed no grant") — that line is precisely what lets an operator
    attribute a foreign log to another pass rather than to their own click.
- **All grant classes render, fixture included.** The record is of acts, and a
  self-describing `fixture-*` tag is cheaper and more honest than a filter
  whose exclusions have to be argued; if fixture noise proves real, narrowing
  is a later decision on its own evidence, not a default here.
- **A fixture asserts the built disclosure lines** — that a recorded consume
  and a recorded claim appear in the rendered output, and that the empty case
  renders its typed empty line. Assert the built string, never the source that
  builds it (§4's own vacuity rule).

## Acceptance

1. A `--spawn` pass that consumed a grant prints, at its close, a disclosure
   line naming that grant (PR, round, tag) and a line naming each spawn log it
   claimed this pass.
2. A pass that spawned nothing and consumed nothing prints the typed empty
   disclosure rather than omitting the lines.
3. The record is populated only at `spawn()`'s claim write and
   `consume_grant()` — no code path reads the global directory to reconstruct
   it.
4. The embedded fixture pass covers 1 and 2 and fails on a mutation that
   drops the empty-case line.
