Umbrella: https://github.com/tim-nish/kogaki/issues/70. On conflict, the
umbrella issue wins. `specs/SPEC.md:152` already sites spawn orchestration in
the lane-command layer, so this story owes no spec amendment.

As the Kogaki repository owner, I want the reviewer tiered to what it is
reviewing, its report posted once, and each run's cost visible at the PR, so
that a one-line fix stops inheriting a ceiling built for a security rewrite —
and so that tier tuning gets its data without another investigation.

## Context

kogaki#70's sinks 4 and 5 plus its observability line. The reviewer is pinned
`opus` with a 60-turn cap regardless of subject (`tools/review-sweep.sh`
`REVIEW_MODEL`/`REVIEW_MAX_TURNS`). The mechanism to tier already exists and is
already used: the fixer split runs `sonnet` under `$KOGAKI_FIX_MODEL`, so this
extends a shipped pattern rather than introducing one.

**PR #67 was the right class for opus** — it rewrote the review pipeline's own
security path. The defect is that every one-line fix inherits the same ceiling.

## Acceptance criteria

1. **Given** a PR is about to be reviewed, **when** its tier is resolved,
   **then** the tier is computed from the **diff's paths**, not the branch
   name: `spec/**`, `specs/**`, `checks/**`, `policy/**` and
   `.claude/hooks/**` → `opus`; ordinary `direct/`/`story/` code → `sonnet`
   with a turn cap of roughly 24.

2. **Given** a diff whose paths match **no** declared class, **when** the tier
   is resolved, **then** it defaults to **`opus`** — the fail-safe side. This
   is the fork the served surface did not discriminate across two framings
   (kogaki#70's policy verdict records both queries), decided on the
   asymmetry: a needlessly expensive review costs about $3, while a too-cheap
   review of an unclassified diff **passes the gate silently**, which is the
   failure the presence check cannot see.

3. **Given** the branch name and the diff paths disagree, **when** the tier is
   resolved, **then** the **diff wins**. A PR on `direct/71-*` that edits
   `checks/registry.json` is security-relevant by content and cheap by branch;
   resolving on the branch would quietly downgrade exactly the reviews that
   most need the higher tier.

4. **Given** the tier is resolved, **when** the sweep runs — in **`--spawn`
   as well as `--dry-run`** — **then** it names the resolved tier and the class
   that produced it. The dry run alone is not enough and the PR #71 review is
   why: the hook takes the `--spawn` path, so a fallback announced only in the
   preview fires **invisibly on the only path that runs in anger**. Criterion
   2's default is a non-member fallback, and an unobservable fallback is the
   defect kogaki#65 was filed over — "both failures present as NOTHING
   HAPPENING". Where the tier is reached by that fallback rather than by a
   declared class, the line says so explicitly.

5. **Given** a report is ready, **when** it is posted, **then** it is composed
   once to a file and posted once with `--body-file`, and the post is verified
   once. PR #67's round 2 shows **four consecutive `gh pr comment` attempts**
   with the same body — blind retries, each a turn, each risking a duplicate
   comment the presence check would read as an extra segment.

6. **Given** a spawned session finishes, **when** its report is posted,
   **then** the report ends with
   `review-cost: <turns> turns · <min> · $<cost> · model <m>` — all four fields
   come from the `result` record in the stream-json the sweep already captures,
   so this is a rendering of held data rather than new instrumentation.

7. **Given** the four `gh pr comment` attempts on PR #67, **when** this story
   is implemented, **then** it is checked whether they landed **duplicate
   report comments**, and any duplicate is reported rather than silently left
   — a second segment for the same head changes what `decide()` counts as
   rounds.

## The tier table's home — decided here, not deferred

**Decided: the tier table lives in `tools/review-sweep.sh`, beside the model
pin, the turn cap and the grant lists.** Recorded as a decision rather than a
story question because the first draft of this story left it to implementation
("decide at implementation and state the choice") while the PR body declared
`deferred slots: none` — an unnamed deferral, and the PR #71 review marked it
blocking. It was right: a slot named nowhere gets no fill-time decision record.

The served line requires a **declared tier carried by the artifact rather than
a judgment re-made per sweep**
(`consulted: product-lab@f918c5158c718394b3a0e4f10239d75bbb451b74 LESSONS.md:40`),
and the sweep is already where every other spawn declaration is carried — model,
`max_turns`, `REVIEW_TOOLS`, `FIX_TOOLS` — each with an env override and each
readable without running anything.

A separate registry file was considered and refused: it would be a **fourth**
registry beside `checks/`, `gates/` and `deps/`, and
`specs/spec-external-deps/SPEC.md` §2 now states that a fourth owes a harder
argument than the third did — specifically, a field the existing carriers cannot
hold. A tier is a spawn parameter, which `tools/review-sweep.sh` already holds
three of. There is no such field, so there is no such argument.

**deferred slots: none** — and this section is what makes that true.

## File boundaries

Touches `tools/review-sweep.sh`. **Accepted overlap:** story 1.17 may touch the
same file if its scope declaration is parsed. Scheduling edge, never a
`depends_on` — the two changes are independent. **Ordering, named rather than
left to whoever picks up first (PR #71 review): 1.19 lands BEFORE 1.17.** 1.19's
edits are additive spawn-argument and reporting changes; 1.17's, if it parses
the declaration, touch the segmenter that `decide()` and
`checks/check-review-report.sh` both read. Rebasing the additive change onto the
structural one is cheaper than the reverse.
