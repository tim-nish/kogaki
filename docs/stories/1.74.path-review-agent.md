# Story 1.74: The path-review agent — judgment-class application of every composition MUST

## Context

Canonical discussion record: **kogaki#490**. On conflict, the issue wins.

Machine-side block 4 of SPEC-draft-pipeline §4.3's five
(`specs/spec-draft-pipeline/SPEC.md:246-248`). §4.6 rules that every MUST of
the Move-composition design is judgment-class, applied by a review agent,
with the human gate approving results only and **no rule becoming a lint,
even where deterministic processing is possible**
(`specs/spec-draft-pipeline/SPEC.md:343-386`). A composed Candidate has no
judge until this agent exists.

## User story

As the owner about to select a Candidate, I see each Candidate carrying the
review agent's reasoning — grounds, entailment, prohibitions, economy, arc
integrity — so my selection is informed judgment over surfaced reasoning,
never a rubber stamp and never a machine verdict.

## Acceptance criteria

1. **Given** a composed Candidate, **when** path review runs, **then** the
   agent applies **every** MUST of §§4.4–4.8 as judgment per Candidate:
   - the grounds test — Move name deleted, the rationale stands on its
     grounds (§4.5, `specs/spec-draft-pipeline/SPEC.md:329-331`);
   - `entailed` propositions with their entailment reasoning exposed (§4.4,
     `specs/spec-draft-pipeline/SPEC.md:280-282`);
   - the closed unsupported-completion prohibitions, including "a Move never
     creates or broadens the premise for its own applicability" (§4.4,
     `specs/spec-draft-pipeline/SPEC.md:296-304`);
   - semantic economy for in-place Move edits (§4.7,
     `specs/spec-draft-pipeline/SPEC.md:387`);
   - Journey arc integrity — causal order never reversed or severed, with
     the three permissive clauses honored (§4.8,
     `specs/spec-draft-pipeline/SPEC.md:447-479`).
2. **Given** the agent's output, **then** it is **reasoning surfaced on the
   Candidate for the human gate — never a verdict, never a lint** (§4.6
   clauses 1 and 3, `specs/spec-draft-pipeline/SPEC.md:355-365`); the three
   evaluation levels (local Move validity, transition continuity, Thesis
   closure) appear only as surfaced reasoning, not licensed checks
   (`specs/spec-draft-pipeline/SPEC.md:367-380`).
3. **Given** N Candidates, **then** review runs machine-side per Candidate
   and the owner sees only Candidate selection — N does not multiply owner
   questions (kogaki#490's own bound).
4. **Given** the check suite, **then** the review-runs-per-Candidate and
   output-is-reasoning-not-verdict properties are exercised by a registered
   check (admission record complete, or cases in an existing
   honestly-covering member), each failing when its path is broken (assert
   by breaking once) — the check exercises the *plumbing*, never judges the
   judgment (§4.6 clause 3 keeps the MUSTs themselves un-linted).

## Story questions

- **SQ1:** whether the agent is a harness subagent, a prompt block inside
  the composition flow, or a runtime-orchestrated call is the implementer's
  cut; the constraint that survives is that its output rides the Candidate
  into the gate and no verdict machinery appears.

## Non-goals

No lint, no check-suite membership for any composition MUST, no gate of its
own (selection is 1.75's gate), no fine-grained edit application at the gate
(§4.6 clause 2).
