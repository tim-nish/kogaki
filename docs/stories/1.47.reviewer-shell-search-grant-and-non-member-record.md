Umbrella: https://github.com/tim-nish/kogaki/issues/310. On conflict, the
umbrella issue and `specs/spec-external-deps/SPEC.md` §4 win.

As the Kogaki repository owner, I want a spawned reviewer to have a working
shell search, and I want the capability gap this issue found **written into the
non-member register that already exists for it**, so that a good review stops
being downgraded to `report-degraded` for reaching for `grep`, and so the
register stops being empty while a run has met a non-member twice.

## Context

**No spec amendment is owed, and that is a finding rather than an omission.**
`specs/spec-external-deps/SPEC.md` §4 already governs this completely — *"a
capability an act depends on and the registry does not declare is surfaced
report-only with its reason, never silently admitted and never treated as
present"* — so this story is an **instance** of a ratified fallback, not a
contract change. The issue was classified spec-touching at triage and
**reclassified to story-sized on reading §4**; the owner's selected alternative
is unchanged.

Four facts about the shipped code and config this story changes, each read
before writing:

- **The grant set.** `tools/review-sweep.sh:683` — `REVIEW_TOOLS` grants
  `Read,Grep,Glob,Write` and eight `Bash(gh …)` / three `Bash(git …)` shapes.
  **No `Bash(grep…)` shape is present.** `CHECK_TOOLS` (`:673`) adds only
  `Bash(bash checks/<file>:*)` per registered check.
- **The non-member register is empty.** `deps/registry.json` →
  `observed_non_members: []`, whose own note states: *"Nothing in this
  repository detects such an observation mechanically today — entries are
  written by hand when a run meets one."* **A run met one twice on 2026-08-09
  and nothing was written.**
- **The registry already declares this dependency as unverifiable.**
  `deps/registry.json` → `spawned-session-tool-grants`,
  `verification.decidable: false`, reason: *"the grant set belongs to a session
  that does not exist until it is spawned, and the host exposes no read of what
  a future session will be granted."*
- **The false-label class is already characterized and disclosed**, and this
  story does not re-open it. `denied_tools()` (`tools/review-sweep.sh:2427`)
  labels a denial with `terminal_key()` — the command's first three words — and
  `post_stall_comment` publishes the caveat that *"three of the eight labels
  harvested this way turned out to name ALLOWED shapes"* (kogaki#74).

**The round-1 denial in the observed run was a false label.**
`Bash(gh run view)` **is** granted via `Bash(gh run:*)`, and round 2 ran
`gh run view --log-failed` successfully; the command was piped into `grep`, and
per the sweep's own caveat *"a piped or redirected command prints as though its
leading command were refused."* Round 2's `Bash(grep -c …)` is the same act
invoked directly, and labelled correctly. **One cause, two denials.**

The served position that selected this alternative over its two siblings:

> one question asked of any fix batch, **does this end a class or extend a
> list?**, whose value is that a class-ender makes a TESTABLE PREDICTION — the
> stream dries up — while a list-extender predicts nothing and can never be
> wrong.

`consulted: product-lab@ce945eb129fd98c5f568256513fc081443eb0a5e topics/knowledge-architecture.md:71`

Granting the shell search tool ends the class *reviewer reached for search and
was refused*; and recording the observation gives the enumeration a denominator,
which is the difference from *"another entry in the list, arriving as
configuration rather than as a check"*
(`product-lab@ce945eb topics/claude-code-ops.md:89`).

## Acceptance criteria

1. **A reviewer's shell search succeeds.** `REVIEW_TOOLS`
   (`tools/review-sweep.sh:683`) grants a shell-search shape, so a reviewer
   running `<granted command> | grep …` and a reviewer running `grep -c …`
   directly are both allowed.

2. **The shape is exercised HEADLESS before it ships.** This is the file's own
   rule, published in `post_stall_comment`'s caveat and stated in kogaki#74 —
   *"Exercise a shape headless before adding it to `KOGAKI_REVIEW_TOOLS`"* —
   and it is an acceptance criterion here rather than advice, because the
   failure it prevents is exactly the one this issue found: a grant string that
   looks right and refuses at runtime. The run record is cited on the PR.

3. **The non-member observation is written to `deps/registry.json`'s
   `observed_non_members`, with its reason**, per
   `specs/spec-external-deps/SPEC.md` §4's *report-only with its reason, never
   silently admitted*. The entry names the capability (a shell search shape in
   a spawned reviewer session), the two 2026-08-09 observations, and that the
   round-1 label was false. **The register ceases to be empty**, which is the
   half of this story that holds whether or not the grant is granted.

4. **`.claude/skills/review-lane/SKILL.md` states which search tools a reviewer
   has.** Acceptance item 3 of the issue, and it binds under this alternative
   too: a reviewer reads that file while composing, so the grant is only in
   force for a reviewer who knows it exists.

5. **The grant is bounded and the bound is stated.** `grep` reaches the whole
   filesystem while the reviewer already holds a bounded `Grep`; whatever bound
   is chosen is written down beside the grant, so the next reader finds a
   decision rather than a default. The issue does not prescribe the width and
   neither does this story.

6. **No change to `terminal_key()` or to the denial label.** The third option
   the issue offered — re-attributing a piped command's denial to its refused
   member — was **declined at the gate**, and the grounds are recorded so it is
   not re-proposed blind: `tools/review-sweep.sh:1642` already establishes that
   `decision_reason_type: subcommandResults` *"is absent on roughly a fifth of
   events, so it is a weak hint and never a discriminator"*, and
   `terminal_key`'s three-word width is load-bearing for the PreToolUse denial
   gate, *"chosen against a measured failure in BOTH directions"* (`:1656`).
   Re-cutting it would change what gets **blocked**, not only what gets
   labelled.

7. **The existing suites stay green**, including the denial fixtures at
   `tools/review-sweep.sh:3480-3560` which compile the generated gate and
   assert its key rule has not drifted.

## Out of scope, stated rather than discovered

- **The false-label class in general.** Characterized by kogaki#74, disclosed
  in `post_stall_comment`, and explicitly not re-opened here — see AC 6.
- **kogaki#309's stall-comment text**, folded into story 1.42 / kogaki#294. This
  story removes a *cause* of the degraded path firing; 1.42 fixes what the
  comment *says* when it does.
- **The `report-degraded` arm and the `review-report-degraded:` token**
  (kogaki#271 / #294, `specs/SPEC.md` §4 clause 10). Untouched.
- **Any mechanical detector for non-members.** The registry's note states none
  exists and that entries are hand-written; this story writes one entry and
  builds no detector.

## Story questions — unverified, never criteria

- **Is `Bash(grep:*)` the right width?** Left open deliberately by the issue and
  by AC 5. Narrower forms (`Bash(grep -c:*)`, or a path-bounded shape) were not
  tested against the harness's matching rules — **cannot-determine, the grant
  matcher's semantics were not read**.
- **Does the harness match a grant against a PIPED command's members at all, or
  only against its leading command?** If only the leading command is matched,
  AC 1's first half may be satisfied by the *existing* grants and the real gap
  is only the direct invocation. **Unverified — this is what AC 2's headless
  exercise decides**, which is a second reason that criterion is not advice.
