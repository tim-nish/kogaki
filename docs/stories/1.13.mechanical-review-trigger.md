Umbrella: https://github.com/tim-nish/kogaki/issues/34. On conflict, the
umbrella issue and `specs/SPEC.md` §4 win.

As the Kogaki repository owner, I want the review lane to fire on PR-open
without anyone remembering to ask, so that the isolation requirement holds by
construction rather than by the owner's attention.

## Context

`specs/SPEC.md` §4's PR-gate clause is this story's governing text, as amended
for kogaki#34. This is design item 2 — the transport — which the amendment
deliberately leaves to the implementing story: the clause binds the property
(every PR receives a report authored outside the authoring session before
merge) and its presence check, not the mechanism.

`depends_on: 1.12` is real, not stylistic. There is nothing to trigger until
the lane emits a report in a shape the presence check can find, and 1.12 is
where that shape is decided.

**A spawned session satisfies the isolation requirement by construction**,
which is the property that makes a mechanical trigger the right carrier rather
than merely a convenient one: a fresh reviewer holds none of the author's
context, so the isolation is a consequence of the transport instead of a rule
someone must observe.

**The transport choice is not a free one, and the spec's silence is not
permission.** The founding constraint is that a rule binds only the occasions
its carrier is installed on, and that per-repo installation makes coverage an
enumeration in which the next repository is uncovered by default. Kogaki is
one repository today and the review lane is repo-local
(`.claude/skills/review-lane/`), which is why kogaki#34's framing is
acceptable here — but the alternatives should be weighed against what happens
if the lane later travels with the client kit, rather than discovering that
question afterwards.

## Acceptance criteria

- **Given** a PR opened against the default branch, **when** it is opened,
  **then** a review-lane run is invoked without any human instruction
  (`specs/SPEC.md` §4, PR-gate clause).
- **Given** that invocation, **when** it runs, **then** it runs in a session
  that did not author the work under review — satisfied by construction if the
  transport spawns a fresh session, and **stated as the reason** the chosen
  transport was chosen (kogaki#34 item 2).
- **Given** the review lane, **when** a run is wanted outside PR-open,
  **then** the on-demand path still works unchanged — mechanizing the trigger
  removes the *remembering*, never the ability to ask.
- **Given** the chosen transport, **when** it is recorded, **then** the story's
  own summary states which occasions it binds and which it does not — a
  transport that covers PR-open but not, say, a reopened or force-pushed PR is
  acceptable, and a transport whose gaps are undisclosed is not.
- **Given** a trigger failure (the run does not fire, or fires and errors),
  **when** it happens, **then** the failure is **observable** rather than
  silent: the presence check from 1.12 is what turns a missed run into a
  visible absence at merge, and this story must not assume the trigger's own
  success.

## Story questions (unverified — not acceptance criteria)

- **The transport is undecided and this story chooses it**: a
  GitHub-Actions-invoked agent, a scheduled routine sweeping open PRs, or an
  owner-side trigger. They differ in what they cost, what credentials they
  need, and — the part worth weighing explicitly — whether they travel with the
  repository or with the machine.
- **Whether a scheduled sweep satisfies "before merge" is unverified.** A
  sweep firing on an interval can lose a race with a fast merge; PR-open
  invocation cannot. If a sweep is chosen, the presence check is what closes
  that race, and the dependency should be stated rather than assumed.
- **Whether an Actions-hosted agent can hold the gateway seam is
  cannot-determine from this repository**: the gateway's location is
  machine-local configuration by design (`specs/SPEC.md` §4 rider; the kit's
  resolution order), and a CI runner has no such configuration. A review lane
  that cannot consult is a review lane running degraded — decide at
  implementation whether that is acceptable for this role, and state it.
