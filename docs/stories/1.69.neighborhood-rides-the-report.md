# Story 1.69: The report renders the provenance-neighborhood section, and the standalone post-gate act retires

## Context

Canonical discussion record: **kogaki#473**. On conflict, the issue wins.

SPEC-terrain §13 v20 (merged at PR #475, `e9c509d`, licensed by kogaki#472)
re-sites the provenance neighborhood: it is a **section of the Full Report**,
computed inside the report pull, seeded by the entered ID set. The standalone
post-gate act is superseded. This story is the implementation half — without
it, live clause text names a section no code writes (§13.7's own
spec-ahead-of-code interval, which this story closes).

**Five findings carried onto #473 from PR #475's two review rounds are in
scope where the issue's items already cover them, and named where they widen
the wording** — see the story questions.

## User story

As the owner pulling a Full Report, I read the Glosses and the provenance
neighbors together in one artifact, so the neighborhood can inform the Strand
selection instead of arriving after it — and no standalone act can render the
section too late or outside the grammar.

## Acceptance criteria

1. **Given** a `report` pull with the full flag set (`--survey --tag --ids
   --claims --subdivisions --judge-model --judge-effort`), **when** it writes
   `reports/FullReport.md`, **then** the file carries a
   `## Provenance neighborhood` section — once, last (SPEC §12 v8) — computed
   by the enumeration machinery `cmdNeighborhood` already holds
   (`resolveEnteredIds`, `settledSlugs`, the seam walk at `NEIGHBORHOOD_BOUND`
   — `terrain/terrain.mjs:2816` — and `neighborhoodOf` at `:2894`), **reused,
   never re-derived**, re-targeted at the Markdown line classes
   `report-format.json` v6 declares.
2. **Given** the render path, **then** the section passes through the same
   `emitOrRefuse("full_report", …)` validation as the rest of the report
   (call sites at `terrain/terrain.mjs:2579` and `:2628` per the issue's
   `searched:` line, re-verified at implementation) **before** the write.
3. **Given** `node terrain/terrain.mjs neighborhood …`, **then** it exits
   non-zero through `fail()` naming the report as the replacement and
   pointing at `reports/FullReport.md` — never a silent no-op, matching how
   `--all-groups`/`--group` retired.
4. **Given** `.claude/skills/terrain/SKILL.md`, **then** step 7 (the
   post-gate neighborhood act, `:296` region) is removed; step 4 states the
   report carries the section and restates the four §13.4 obligations
   against it; the §6.3 two-act window is stated unchanged (the neighborhood
   is computed inside act 2, never a third act); the flow ends at step 6.
5. **Given** `checks/check-terrain-composition.sh` against the stub gateway,
   **then** five new cases run and each fails when its write path is broken
   (asserted by breaking it once during implementation): (a) a pulled report
   contains the section conformant under v6; (b) same identity twice →
   identical section; (c) `N<n>` IDs disjoint from `L<n>` inside the report;
   (d) an empty enumeration renders the explicit empty lines, never an absent
   section; (e) the subcommand refuses with the pointer text.
6. **Given** `checks/fixtures/terrain/format/full-report.md`, **then** it
   carries a **non-empty** neighborhood section (SPEC §14.5 at v20 states
   this obligation in the owed tense and names #473 as the carrier), and
   §13.1's parallel present-tense sentence at `specs/spec-terrain/SPEC.md:3673`
   becomes true or is amended in the same diff — the two sites must agree
   (PR #475 round 2, carried finding).

## Story questions

- **SQ1 (carried finding, item 2's guarantee):** `report-format.json` v6's
  allowlist is **inert on `full_report`** (three bare-placeholder body
  classes; a malformed line falls through and is admitted), so "a
  nonconformant section reaches neither the terminal nor the file" is not
  deliverable by the allowlist alone. The carried fork
  (`deferred_slot_full_report_allowlist`) offers: restate the guarantee
  against what v6 enforces, or take the slot's fork (constrain the three
  body classes / a sectioned allowlist) as part of this issue. **A decision
  is owed at implementation and recorded on #473** — not silently embedded.
- **SQ2 (registry row):** `checks/registry.json:122`'s `terrain-composition`
  entry names its removal instrument's act as the PR that brought the
  neighborhood under the grammar — that act occurred (PR #475) and the
  signal did not fire, for the SQ1 reason. This story's check-suite edit is
  where the row is owed its update.
- **SQ3 (register count, informational):** five of v6's sixteen class notes
  cite a source line one-off from the `say()` they describe — recorded on
  #473; repair them opportunistically if the notes are touched, else leave
  to the register.
