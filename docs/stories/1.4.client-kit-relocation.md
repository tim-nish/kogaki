Canonical discussion: https://github.com/tim-nish/kogaki/issues/9 (kogaki
half, items 1–5; the gateway half is item 6, carried in tsurezure-gateway —
on conflict, the issue wins).

As the Kogaki repository owner, I want the Client Kit to live inside Kogaki
with the gateway located only by machine-local configuration, so that the
gateway repository stays a server and nothing else, and the kit's consumer
half stops depending on paths that resolve to nothing in a consumer.

## Context

Owner ruling 2026-08-05: the kit lives inside Kogaki until a second consumer
installs it, then separates into its own repository. The 2026-08-05 audit
found the design model held behaviorally (zero `client-kit` references in
gateway `src/`) and broke in packaging at three sites: colocation defaults at
`install.sh:7` and `bin/gateway-query.mjs:26`, and `client-kit/bin/…`
references in the consumer's managed block that resolve to nothing here.

## Acceptance criteria

- **Given** the kit relocated under `policy/kit/` (layout is the
  implementer's to refine and state in the PR; the directory follows
  kogaki#3's consumer-package convention), **when** its round-trip and
  degrade tests run, **then** they pass **with the gateway repository absent
  from every default path** — the gateway is located by `--gateway`, an env
  var, or the machine-local MCP registration, never by directory adjacency
  and never by a committed path.
- **Given** a fresh session in this repository, **when** the harness loads
  skills, **then** the consult-first skill loads from
  `.claude/skills/consult-first/` — it has been a dead pointer since the
  first install (2026-08-05 finding).
- **Given** `CLAUDE.md`'s managed block, **when** a reader follows any path
  it names, **then** that path exists in this repository.
- **Given** any kit tool, **when** it runs, **then** it reads no
  `~/.tsurezure/` internals — asserted in the install test. This is
  `policy/consultation-map.md` entry 2 and `specs/SPEC.md` §4's
  sided-evidence clause, both landed at kogaki#7
  (`consulted: product-lab@bb68ccf topics/archive/knowledge-architecture.md:271`).
- The gateway half (delete `client-kit/` from tsurezure-gateway, its suite
  still passing) is **out of this story's scope** — it is carried by the
  handoff issue filed against that repository at triage.
