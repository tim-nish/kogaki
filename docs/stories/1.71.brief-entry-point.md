# Story 1.71: The Brief entry point — a `brief` skill and runtime minting `briefs/<slug>/brief.md` from LessonDisplayIDs

## Context

Canonical discussion record: **kogaki#482**. On conflict, the issue wins.

SPEC-draft-pipeline §5.3 (v7, decided at the #482 gate 2026-08-16) lands the
Brief's durable home — a **directory per Brief**, `briefs/<slug>/brief.md`,
tracked — and the entry point: a new `brief` skill fronting a runtime, outside
Terrain, input unit `LessonDisplayID` and nothing else. This story builds it.
The live composition workflow, the Step record and the path-review agent stay
uncarried per kogaki#127's promotion rule — this is the entry point only.

## User story

As the owner who has settled a Strand set on a pulled Full Report, I start a
Brief by naming the `L<n>` ids I settled on, and get a durable, enumerable
document in the tree carrying my Strands with their pins and every
composition field as a typed unfilled slot — so the next sitting resumes from
the artifact rather than from memory.

## Acceptance criteria

1. **Given** `brief/brief.mjs start --survey <record> --ids L2,L1 --slug
   <slug>`, **then** `briefs/<slug>/brief.md` is created carrying: the
   reader-facing definition of "brief" (§5.3, per `articles.md:132`); each
   selected Strand resolved from the survey record (slug, display id, cite,
   pin); and every §5.1 field (`thesis`, `sequence`, `reader_start`,
   `reader_target`, `opening_question`, `strand_coverage`, `thesis_closure`,
   `tradeoffs`, the §5.2 ledger) present as a **typed unfilled slot**, never
   omitted.
2. **Given** an id the survey record does not carry, **then** the run
   refuses, naming what was entered and what the record holds — never a
   silent drop (§3's completeness rider at entry).
3. **Given** a `G<n>` or `G<n>-<m>` id anywhere in `--ids`, **then** the run
   refuses **by name**, stating that grouping ids are per-report-identity
   tokens and pointing at the report's member headings for the `L<n>` ids
   (§5.3; SPEC-terrain §12.1/§14.3).
4. **Given** an existing `briefs/<slug>/`, **then** the run refuses rather
   than overwriting — the entry point is a creator, never an editor (§5.3
   idempotence-by-slug).
5. **Given** `.claude/skills/brief/SKILL.md`, **then** it fronts the runtime
   (inputs composed by the session, artifact handed over, never retyped —
   the delivery discipline SPEC-terrain §14.4/§14.4.1 established and
   `articles.md:131` grounds), defines "brief" where the owner reads it, and
   states the Terrain boundary: the skill starts from an already-settled set
   and never fetches or widens one.
6. **Given** the check suite, **then** the four refusal/mint properties
   above are exercised by a registered check (a new member with its
   admission record complete — stage, budget, removal signal declared at
   birth — or cases in an existing member if one honestly covers the
   surface), each failing when its path is broken (assert by breaking once).

## Story questions

- **SQ1 (format of the unfilled slots):** §5.1 names the fields; §5.3 fixes
  presence-as-typed-slots. The concrete Markdown shape of a slot (heading +
  typed `*(awaiting composition)*` line, or a fenced block) is the
  implementer's, recorded in the check's fixture — not a spec question
  unless a reader-facing ambiguity appears.
- **SQ2 (informational):** two new top-level directories land — `briefs/`
  (the declared **product** class, widening the footprint contract by one
  exactly as `articles.md:45` says it should; nothing else lands there) and
  `brief/` (the runtime's home, the `terrain/terrain.mjs` siting convention
  applied — a tool home, not a product class).

## Non-goals

No composition, no steps, no Moves, no path review, no checkpoints/resume
format (homed by §5.3, designed by a future item-5 sitting), no Terrain
amendment, no Thesis invention.
