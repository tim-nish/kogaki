# Story 1.70: the move-ingest selection screen is an artifact the tool writes

Canonical discussion record: https://github.com/tim-nish/kogaki/issues/474

**As** the owner ingesting Moves,
**I want** the selection screen I accept against to be a file the tool wrote,
**so that** the screen cannot silently lose rows between the parser and my eyes.

## Why this story exists

The first live `/move-ingest` run (2026-08-16, 22 Moves) reached the owner as
model-retyped text and truncated mid-identifier at row 16 of 22. The owner
accepted "all" having been shown 15½ of 22 rows. The saved result happened to be
correct because `save_accepted` is mechanical (`tools/move_ingest.py:492`), but
the screen the acceptance was taken on was incomplete and nothing in the flow
could notice.

The spec half landed with issue #474's sitting: `specs/SPEC.md` §2.5.3 now rules
cross-surface that an owner-facing screen is delivered as an artifact the
mechanical half writes, and `specs/spec-draft-pipeline/SPEC.md` §6.9.2 (v2)
cites it and names this surface's artifact. **This story is the tool and skill
half. It is not born-satisfied: no code in the repository writes the file today.**

## Grounding — read before writing criteria

- `render_screen(proposals)` **already exists** at `tools/move_ingest.py:612`
  and already emits the §6.9.0 count line first and unconditionally
  (`tools/move_ingest.py:619-627`). This story does not add a renderer.
- `main()` **prints that string to stdout** at `tools/move_ingest.py:663` —
  the channel `specs/SPEC.md` §2.5.3 rules unavailable. That line is the defect
  site.
- `render_screen` today emits admission rows only
  (`tools/move_ingest.py:628-635`); it accepts no readings input and writes no
  file.
- `save_accepted` (`tools/move_ingest.py:492`) and the collision rules are
  **untouched** by this story.
- `self_test()` at `tools/move_ingest.py:692` is the existing harness the new
  cases join.

## Acceptance criteria

1. **Given** a Moves file parsing to N records,
   **when** `python3 tools/move_ingest.py <file>` runs,
   **then** `reports/MoveScreen.md` exists and contains exactly N proposal rows,
   and the parsed-record count line is its first line.

2. **Given** a prior run wrote `reports/MoveScreen.md`,
   **when** the tool runs again,
   **then** the file is overwritten, not appended — the fixed-literal,
   overwritten-per-render discipline of `specs/SPEC.md` §2.5.3.

3. **Given** a record refused at admission,
   **when** the screen is rendered,
   **then** that record's row carries its refusal condition and line number
   verbatim, as the stdout rendering does today
   (`tools/move_ingest.py:635`).

4. **Given** a typed readings input (id → reading string) naming an id outside
   the parsed set,
   **when** the screen is rendered,
   **then** the render is **refused naming the stranger id**. An id with no
   reading renders no reading line — absence is the normal case, not a gap.

5. **Given** any input,
   **when** the screen is rendered,
   **then** no per-row verdict, score or status token is renderable — the
   property is **unwritability, not prohibition**, per `specs/SPEC.md` §2.5.3's
   closing clause and §6.9.2's *"no verdict machinery and no lint"*.

6. **Given** `.claude/skills/move-ingest/SKILL.md` step 3,
   **when** the skill runs,
   **then** it names `reports/MoveScreen.md` to the owner as the first act after
   the command returns, and retyping, summarizing or tabulating the screen into
   the reply is prohibited on §2.5.3's grounds. Acceptance stays the owner's
   chat act against the artifact's numbering.

7. **Given** `python3 tools/move_ingest.py --self-test`,
   **when** it runs,
   **then** it exercises criteria 1–5 and passes — **and the row-count case is
   verified by deliberately breaking the write once and confirming the check
   fails**, per issue #474's own acceptance wording.

## Out of scope — each is its own decision

- No free-form/prose authoring stage; the column-0 `id:` grammar and the four
  admission conditions are unchanged.
- No kogaki#177 work. The 2026-08-16 ingestion did **not** discharge #177.
- No changes to admission, normalization, save, INDEX, or the §4.2 field set.
- No gate-carrier/AskUserQuestion binding for the selection — 22 rows cannot
  ride a 4-option selector.

## Story questions — unverified, not criteria

- The exact serialization of the typed readings input (CLI flag taking a JSON
  path, mirroring Terrain's `--claims` pattern, versus stdin) is **not
  established from shipped code in this repository** — Terrain's `--claims` was
  named in issue #474 as a model, not read here. The implementer reads the
  Terrain renderer and follows it, or states the divergence.
