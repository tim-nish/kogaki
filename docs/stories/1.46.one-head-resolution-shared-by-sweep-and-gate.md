Umbrella: https://github.com/tim-nish/kogaki/issues/308. On conflict, the
umbrella issue and `specs/SPEC.md` §4 clause 7 win.

As the Kogaki repository owner, I want `tools/review-sweep.sh` and
`checks/check-review-report.sh` to answer *"is this head reviewed?"* through
**one definition**, so that a head which moved without changing content stops
costing an owner grant and a review round.

## Context

`specs/SPEC.md` §4 **clause 7** is this story's governing text, amended to v2
for kogaki#308 in the same sitting that filed this story: *"'this head is
reviewed' resolves through ONE definition — the subject/instrument rule above,
sha as instrument and content as subject — consumed by both
`checks/check-review-report.sh` and `tools/review-sweep.sh`, with a fixture
asserting the two agree."* §4 clause 9 row 4 is re-typed to name both
consumers.

Three facts about the shipped code this story changes, each read before
writing:

- **The gate's resolution knows about carry-forward.**
  `checks/check-review-report.sh:388` — `head_segments(segs, head, carried=())`,
  whose docstring states *"a carried segment is this head's segment for every
  purpose below — presence, open-blocking, completeness and scope"*. It is fed
  by `carry_forward()` (`checks/check-review-report.sh:559`), which recomputes
  both diffs and records each `base..rev` range with its digest.
- **The sweep's does not.** `tools/review-sweep.sh:2759` —
  `head_segments(segs, head)`, no `carried` parameter, body
  `[s for s in segs if same_head(head, s['sha'])]`: sha prefix identity only.
  Its own docstring already names the defect this story fixes — *"'this head'
  is one question, and the presence side and the budget side answering it
  differently is precisely the two-instruments-disagree shape this file was
  already carrying."*
- **Both sides are already injection-shaped**, which is why the fix costs no
  testability: `decide()` (`tools/review-sweep.sh:2865`) takes `resolves` as a
  callable, and `carry_forward()` takes `diff_at` and `merge_base` as callables
  *"so the fixture pass exercises every branch with no repository and no
  network"*.

**The carrier shape is precedented in the file being changed.**
`tools/review-sweep.sh:1656` holds `TERMINAL_KEY_SRC`, one rule as a source
string consumed by two processes, on the stated ground that *"two hand-written
copies of a rule are two things that can disagree — the defect this file has
already found twice, once per call site"*, with a fixture at `:3506` compiling
both and asserting agreement. Clause 7 v2 mandates **one definition and an
agreement fixture**, not that specific mechanism.

## Acceptance criteria

1. **One definition, two consumers.** The head-resolution unit — `same_head`,
   `head_segments(segs, head, carried)` and `carry_forward` — exists in exactly
   one place, consumed by both `checks/check-review-report.sh` and
   `tools/review-sweep.sh`. A second implementation of the resolution in either
   file fails this criterion.

2. **A fixture asserts the two agree**, on the pattern the file already uses
   for `terminal_key` (`tools/review-sweep.sh:3506`, which compiles the
   generated gate and asserts its key rule has not drifted from the one
   definition). The fixture fails if the two consumers are made to disagree.

3. **A moved head with an unchanged diff does not produce `spawn-round-N`.**
   Given a PR whose head moved and whose diff against its base is
   byte-identical to the diff a prior report reviewed, and rounds remaining,
   `decide()` returns the state that head's carried report justifies — not a
   new round.

4. **The same case does not produce `park` on a PR the gate would merge.**
   With the rounds spent, `decide()` does not return `park` for a head the gate
   resolves as carried. The live specimen is PR #307, head `ae9d85f`, merged
   2026-08-09 on a green gate while the sweep reported *"PARKED — 2 rounds
   spent and ae9d85f is still unreviewed"*.

5. **`FIX` carries the moved-head/identical-diff case, and it fails before the
   fix.** The table at `tools/review-sweep.sh:3581` has no such case today, and
   three of its eight cases (*"one stale report -> round 2"*, *"two stale
   reports -> park, never a third round"*) encode the sha-only reading as
   correct — so the suite certifies the shape it was built in. The new case is
   demonstrated red against the pre-change code.

6. **`decide()` stays pure and its fixtures acquire no repository.** The two
   git reads the resolution needs are **injected** on the established pattern —
   the way `resolves` already is, and the way `carry_forward()` already takes
   `diff_at` and `merge_base`. An implementation reaching for `git` inside
   `decide()` fails this criterion even where it computes the right answer.

7. **The round counter is untouched.** A carry-forward is not a round and
   consumes none of clause 3's bound — `specs/SPEC.md` §4 clause 7. The
   existing rounds fixtures (`rounds pass: 4/4`) stay green unchanged.

8. **The existing green suites stay green.** `checks/check-review-report.sh`'s
   full pass — 18 discrimination, 15 declaration, 7 base, **12 carry-forward**,
   11 blocked-dimension, 16 boundary, 5 trust, 4 rounds — is re-run and
   unchanged except for additions.

## Out of scope, stated rather than discovered

- **The `review-base:` line's own contract** (§4 clause 7 resolutions (a)/(b)/
  (c), kogaki#96). Read, not changed. `tools/review-sweep.sh:922` writes the
  reviewer's instruction to emit it and stays as it is.
- **kogaki#288**, the mirror direction (sweep says `done`, gate refuses,
  clause 10's unadjudicated earlier-head blocking). A different transition with
  a different carrier.
- **kogaki#269 and kogaki#270**, severity transitions and the transition
  enumeration. Row 4 is re-typed here; rows 2 and 3 are theirs.
- **The two-round bound itself** (kogaki#72, clause 3). Untouched in value and
  in unit.

## Story questions — unverified, never criteria

- **Can the two files share source at all without a third carrier?**
  `tools/review-sweep.sh` already `exec`s a source string it generates itself
  (`:1683`, `:3509`), but **no cross-file import between `tools/` and
  `checks/` was located** — cannot-determine, implementation not read for this
  path. Whether the shared unit lives as a source string in one file read by
  the other, or in a new third carrier, is the implementer's call under AC 1
  and AC 2, which bind the property and not the mechanism.
- **Does any registered check assert the fixture counts printed above?** Not
  verified. If one does, its expected counts move with AC 5's addition.
