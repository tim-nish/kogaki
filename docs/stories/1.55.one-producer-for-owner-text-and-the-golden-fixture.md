## Story

As the owner reading a terrain screen, I want to read the artifact the runtime
wrote rather than a model's retyping of it, and I want a checked-in conformant
specimen to fail a renderer edit in the PR — so that the emit-time refusal
story 1.54 installs actually reaches my eyes, and so that drift is caught
between hands-on rounds instead of during them.

## Acceptance criteria

**AC1 — the skill delivers the artifact, never a quotation of it.**
Given `.claude/skills/terrain/SKILL.md`,
when the flow reaches a point where the owner reads a screen or a report,
then the instruction is to deliver the file or stream the runtime wrote (e.g.
`cat` the artifact `announceArtifacts` named), and the file states plainly that
retyping, summarizing or re-formatting runtime output into a reply is
prohibited.

**AC2 — the prohibition is stated as a removal, not a policing duty.**
Given AC1's wording,
when a reader asks what checks it,
then the answer is that the relay is no longer a producer — per §14.4, *"nothing
new is prohibited, so nothing new has to be policed"*. A criterion demanding a
lint over model output would be the detect-side answer this decision declined.

**AC3 — the golden fixture exists and is conformant.**
Given `checks/fixtures/`,
when the suite runs,
then it holds **one specimen per surface the grammar covers** — two at v14, one
of the Full Report owner rendering and one of the co-tag screen — both
conformant against `specs/spec-terrain/report-format.json`. This is §14.5's own
per-covered-surface count, not a widening of it.

**AC4 — the fixture is wired into the suite.**
Given `checks/check-terrain-composition.sh`,
when a renderer edit changes the rendered shape,
then the check fails in the PR, naming the fixture and the divergence.

**AC5 — the fixture never wins against the grammar.**
Given a disagreement between the fixture and
`specs/spec-terrain/report-format.json`,
when the suite runs,
then the grammar is authoritative and the fixture is what is reported as
stale — §14.1's precedence is one-way and §14.5 restates it. A fixture that can
ratify a shape is a second carrier, which is the defect this decomposition
removes.

**AC6 — the fixture is a specimen, not a corpus.**
Given the fixture set,
when a future format incident occurs,
then the response is a grammar edit and a regenerated specimen — not an
additional fixture per incident. This criterion exists because §14.2 names
"a check suite growing at roughly one member per incident" as the tell, and a
fixture directory is the obvious place for that growth to resume.

## Story questions

- **SQ1.** Is the specimen generated by running the emitters against a
  checked-in survey record, or hand-authored? Generated keeps it honest as the
  emitters change; hand-authored keeps it independent of the code it checks.
  §14.5 does not decide this and neither does kogaki#319 — decide in
  implementation and record the reason beside the fixture.
- **SQ2.** Survey records are uncommitted run-workspace artifacts
  (`specs/spec-terrain/SPEC.md` §12.2 v11), so a generated specimen needs a
  committed input. Whether a minimal synthetic survey record may be committed
  for this purpose is **cannot-determine** — §12.2's non-commit rule is about
  real records carrying real material, and this story does not assert it either
  way.
- **SQ3.** Does `.claude/skills/terrain/SKILL.md` have a source/installed-copy
  split like the consult-first skill (kogaki#285 reports one for that skill)?
  If so, AC1 must land in the source and the equality must hold. **Not read for
  this story** — cannot-determine, raise before editing.
