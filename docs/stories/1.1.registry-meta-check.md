As the Kogaki repository owner, I want the check registry's declaration
enforced by one meta check, so that an unregistered check file is dead code
found mechanically rather than a promise the registry makes and nothing
keeps.

## Context

`checks/registry.json` declares: "An unregistered check file is dead code;
one meta check asserts the registry and the checks/ tree agree"
(`checks/registry.json:5-6`). No such check exists — the declaration is
currently unenforced. The meta check is the producing site for the
registry's own inputs, and it enters through the registry's own admission
record — fittingly, as the first admission
(`consulted: product-lab@bb68ccf topics/knowledge-architecture.md:21` — "the
suite runs only REGISTERED checks and the registry schema REQUIRES the
admission record … an unregistered check file is dead code found by one meta
check rather than a policed behaviour").

## Acceptance criteria

- **Given** a check file under `checks/` absent from
  `checks/registry.json`'s `checks` array, **when** the meta check runs,
  **then** it fails naming the unregistered file. (New behavior — nothing to
  cite.)
- **Given** a registry entry whose check file does not exist under
  `checks/`, **when** the meta check runs, **then** it fails naming the
  dangling entry. (New behavior.)
- **Given** the current repository state (empty `checks` array, no check
  files besides the meta check itself), **when** the meta check runs,
  **then** it passes — the meta check is itself registered, so it is not
  its own counterexample.
- The meta check's registry entry carries the full admission record the
  registry note requires (`checks/registry.json:2-7`): the contract it
  uniquely carries (registry⇄tree conformance), the licensing issue
  (kogaki#2), and a **removal signal declared at birth** — admission is
  judged on "the defect class ended, the tier, the measured runtime, and
  the removal signal"
  (`consulted: product-lab@bb68ccf topics/claude-code-ops.md:19`), so the
  entry also declares its tier (loop position) and measured runtime.
