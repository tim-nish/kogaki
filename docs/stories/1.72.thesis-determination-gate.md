# Story 1.72: The thesis-determination gate — 2–3 plain-register Thesis candidates composed from the settled Strand set

## Context

Canonical discussion record: **kogaki#488**. On conflict, the issue wins.

The first human gate of Brief composition, downstream of the §5.3 mint.
SPEC-draft-pipeline §3 rules the Thesis is read, not invented at entry
(`specs/spec-draft-pipeline/SPEC.md:132-156`), and §5.1 carries the Brief's
`thesis` slot (`specs/spec-draft-pipeline/SPEC.md:594`). What this story
builds is the composition act the 2026-08-17 run surfaced: the owner ran
`/brief` expecting a composed Brief and received the mint alone — kogaki#127's
promotion rule fired, and the Thesis gate is the first uncarried block
downstream of the mint.

## User story

As the owner holding a freshly minted Brief, I am shown 2–3 Thesis
candidates composed from the Strands I settled — in ordinary vocabulary I
could say out loud — and the one I adopt lands in the Brief's `thesis` slot,
so composition proceeds from a thesis I chose rather than one the machine
assumed.

## Acceptance criteria

1. **Given** a minted `briefs/<slug>/brief.md` with an unfilled `thesis`
   slot, **when** the thesis-determination flow runs, **then** 2–3 Thesis
   candidates are composed **from the Brief's settled Strand set only** —
   never fetched, never widened, never invented from material outside the
   Brief (§3's read-not-invented rule,
   `specs/spec-draft-pipeline/SPEC.md:132-156`).
2. **Given** the candidates, **then** each is in plain register with
   round-trip concessions per `specs/spec-style-contract/SPEC.md` §4 (the
   binding SPEC-draft-pipeline §2 row 4 names,
   `specs/spec-draft-pipeline/SPEC.md:88`).
3. **Given** the presentation, **then** it rides the question UI with a
   free-form override, and **the premise's negation is a first-class
   option**: "the settled set is what should change — back through Terrain,
   never a Brief fetch" (the §6 negates_premise discipline applied at this
   gate, `specs/spec-draft-pipeline/SPEC.md:823-829`).
4. **Given** an adopted candidate (or free-form answer), **then** it lands in
   the Brief's `thesis` slot (`specs/spec-draft-pipeline/SPEC.md:594`) and
   nothing else in the Brief is edited by this flow.
5. **Given** no owner answer, **then** nothing is written — the gate blocks,
   exactly as the #487 repair requires of the slug ask; the ask carries its
   gate declaration.
6. **Given** the check suite, **then** the compose-from-settled-set,
   negation-option, and no-write-before-answer properties are exercised by a
   registered check (admission record complete, or cases in an existing
   member that honestly covers the surface), each failing when its path is
   broken (assert by breaking once).

## Story questions

- **SQ1:** whether candidate composition runs in the runtime
  (`brief/brief.mjs`) or in the skill layer with the runtime doing only the
  slot write is the implementer's cut; the constraint that survives either
  way is that the *write* happens only after the owner's answer.

## Non-goals

No Step composition, no Move binding, no Candidate assembly (stories
1.73–1.75), no Terrain amendment, no second style artifact.
