# Story 1.72: The thesis-determination gate and the Thesis-adoption mint

## Context

Canonical discussion record: **kogaki#488**. On conflict, the issue wins.

Re-cut 2026-08-17 to SPEC-draft-pipeline v9 (kogaki#494, owner ruling): Brief
creation runs **entry → thesis-determination gate → mint**. Entry resolves
the settled Strand set (LessonDisplayIDs against the survey record, refusals
unchanged — §5.3); pre-Thesis state is **machine-local run state**, never an
owner artifact; the gate composes 2–3 Thesis candidates; the mint consumes
the adopted Thesis and the owner-approved thesis-derived slug. §3 rules the
Thesis is read from the settled set, not invented
(`specs/spec-draft-pipeline/SPEC.md:143-167`); #494's remedy makes a
pre-Thesis Brief file **unproducible rather than prohibited**.

## User story

As the owner who has settled a Strand set, I run the brief entry, am shown
2–3 Thesis candidates composed from that set in ordinary vocabulary, adopt
one (or answer free-form), approve a slug derived from it — and only then
does `briefs/<slug>/brief.md` exist, carrying my Thesis from birth.

## Acceptance criteria

1. **Given** the brief entry with a resolved settled set, **then** no file
   or directory is created under `briefs/` before a Thesis is adopted —
   pre-Thesis state is machine-local run state (SPEC §5.3 v9 block;
   kogaki#494 remedy: unproducible, not prohibited).
2. **Given** the resolved set, **when** the thesis-determination gate runs,
   **then** 2–3 Thesis candidates are composed **from the settled Strand set
   only** — never fetched, never widened, never invented from outside it
   (§3, `specs/spec-draft-pipeline/SPEC.md:143-167`), each in plain register
   with round-trip concessions per `specs/spec-style-contract/SPEC.md` §4.
3. **Given** the presentation, **then** it rides the question UI with a
   free-form override, and **the premise's negation is a first-class
   option**: "the settled set is what should change — back through Terrain,
   never a Brief fetch" (the §6 negates_premise discipline,
   `specs/spec-draft-pipeline/SPEC.md:900-906` region), and the ask carries
   its gate declaration.
4. **Given** an adopted Thesis, **then** exactly **one slug candidate
   derived from it** is presented through the question UI for approval, with
   free-form override; the approved slug names `briefs/<slug>/` (§5.3 v9).
   No slug candidate exists before adoption.
5. **Given** the approved slug, **then** the mint creates
   `briefs/<slug>/brief.md` with the `thesis` field **filled at mint by
   construction** and every downstream §5.1 field a typed unfilled slot;
   entry-time refusals (unknown `L<n>`, `G<n>`/`G<n>-<m>` by name,
   slug collision) are unchanged from §5.3.
6. **Given** no owner answer at either ask (Thesis or slug), **then**
   nothing is written under `briefs/` — the gate blocks.
7. **Given** the check suite, **then** the no-write-before-Thesis,
   compose-from-settled-set, negation-option, thesis-derived-slug-approval,
   and thesis-filled-at-mint properties are exercised by a registered check
   (admission record complete, or cases in an existing member that honestly
   covers the surface — `checks/check-brief-entry.sh` is the sitting
   candidate), each failing when its path is broken (assert by breaking
   once).
8. **Given** the corrected flow landing, **then** the specimen
   `briefs/derived-artifacts/` is **removed** (owner's recorded answer,
   2026-08-17: remove and re-mint through the corrected flow — the re-mint
   itself is a live owner act, not this story's).

## Story questions

- **SQ1:** where the machine-local pre-Thesis run state lives (in-session
  memory vs. a scratch record) is the implementer's cut; the constraint that
  survives is that nothing lands under `briefs/` or any tracked path before
  adoption.

## Non-goals

No Step composition, no Move binding, no Candidate assembly (stories
1.73–1.75), no Terrain amendment, no second style artifact, no re-mint of
the specimen's content (an owner act at a live sitting).
