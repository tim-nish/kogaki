umbrella issue and `specs/spec-terrain/SPEC.md` §8 win.

As the Kogaki repository owner, I want a large group to subdivide into
LLM-classified SubGroups each carrying its own composed claim, built and
runnable but **not offered by default**, so that I can dogfood its output and
verdict it before it replaces the co-tag step rather than after.

## Context

`specs/spec-terrain/SPEC.md` §8 is the governing text and it **closes v1
§5's open slot** — v1 read "Whether Kogaki's Terrain ports it is not decided
by this spec"; v2 decides that it does.

Subdivision is **placement plus title-derivation, hiding none** — "a cap
decides WHICH members appear, subdivision decides WHERE each appears and
hides none" (`topics/articles.md:66@f918c515`). It is therefore inside the
presentation-only invariant and is **not** the refused within-axis cap.

**§8.1 is the rider that shapes this story's scope.** The ordering
implemented → dogfooded → owner-verdicted → offered is inherited from the
journey-similarity precedent, and merging this story's code **arrives at**
the offering gate rather than discharging it: "merged code evidences
existence, never the gate's standing"
(`topics/articles.md:53@f918c515`). **Co-tags stay the default for a run
naming no substrate.** The hub-side offering gate is undischarged at
`product-lab:q_a/staging/2026-07-31-subdivision-offering-measurement-due.md`,
and this reimplementation inherits the ordering, not the discharge.

## Acceptance criteria

- **Given** a group selected for subdivision, **when** it renders, **then**
  the order is **GroupClaim first, then the SubGroups each with its own
  composed claim, then the Lessons per SubGroup**
  (`specs/spec-terrain/SPEC.md` §8).
- **Given** subdivision runs, **when** members are placed, **then** **no
  member is hidden**: every member of the parent group appears in at least
  one SubGroup, and members that fit none appear in an **explicit named
  SubGroup** — completeness is a cover counted in placements, checked
  **after** composition (`specs/spec-terrain/SPEC.md` §2.1, §8).
- **Given** a candidate SubGroup, **when** the stop condition is evaluated,
  **then** the leaf condition is **CONJUNCTIVE**: it is a leaf when its claim
  **composes honestly AND is tighter than its parent's**. Failing the first
  splits further; failing the second reports that the split bought nothing
  (`specs/spec-terrain/SPEC.md` §8).
- **Given** a composed claim that **trails into enumeration**, **when** it is
  emitted, **then** the **degenerate-claim disclosure** fires
  (`specs/spec-terrain/SPEC.md` §8).
- **Given** a claim that is honest but **true of every member at the size
  served**, **when** it is emitted, **then** the **undiscriminating-claim
  disclosure** fires — the two disclosures are **disjunctive**, because the
  first alone does not detect the reported condition
  (`specs/spec-terrain/SPEC.md` §8).
- **Given** the three instruments — 20% of placements, the screen budget,
  at-a-glance legibility — **when** they are implemented, **then** they
  measure **three different quantities** and **none is a member-count
  threshold**; the owner's "above ~4 members" is calibration evidence. **A
  member-count threshold appearing in this story's code is a defect against
  `specs/spec-terrain/SPEC.md` §8.**
- **Given** a run that names no substrate, **when** it renders,
  **then** **co-tags are the default** and subdivision is **not offered** —
  it is reachable only by explicitly naming it
  (`specs/spec-terrain/SPEC.md` §8.1).
- **Given** subdivision output, **when** it is produced, **then** it is
  **capturable as a dogfood specimen** — the run writes its subdivision
  record to the machine-local run workspace so the offering gate has a
  specimen to be verdicted on (`specs/spec-terrain/SPEC.md` §8.1;
  `specs/SPEC.md` §4 rider 3).
- **Given** subdivision, **when** it acts, **then** it **ranks, trims and
  hides nothing** — those still route through the proposal contract, and the
  >3-option trim guard at the selection gate stands
  (`specs/spec-terrain/SPEC.md` §8.2).
- **Given** any count a SubGroup emits, **when** it renders, **then** it
  names its families and states its denominator in Lessons
  (`specs/spec-terrain/SPEC.md` §9).

## Story questions

- **The offering gate is NOT an acceptance criterion of this story, and the
  exclusion is deliberate.** "The owner has verdicted subdivision's output"
  cannot be satisfied by an implementing PR, and writing it in would make
  this story born-undischargeable — its body would declare its own exclusion
  from the command implementing it. It is therefore **parked with its
  trigger**: the gate fires when a dogfood specimen exists and the owner
  verdicts it, and until then co-tags remain the default. **Merging this
  story does not discharge the gate**; it makes it due.
- **Which model performs the classification, and the prompt it is given, are
  implementation and are not specified here.** §8 binds the leaf condition,
  the two disclosures, the three instruments and the completeness cover — not
  the classifier.
- **Recursion depth is not fixed by the spec.** §8 says "one level down" of
  the *substrate*, and the leaf condition is what terminates the split. A
  hard depth constant would be the member-count threshold in another unit.
