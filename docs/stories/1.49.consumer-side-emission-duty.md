As the owner of the portfolio, I want a kit-installed sitting that produces a
durable learning to emit its staging candidate in the same sitting, unasked, so
that consumer-side findings stop reaching the hub only when I personally notice
one and relay it — the path that carried both the verification-binding class
(kogaki#243) and the vocabulary-fragmentation finding (kogaki#268), and that has
no owner otherwise.

## Context

The contract for this story was written in the same sitting that files it:
`specs/spec-client-kit/SPEC.md` §4 (v1), decided as alternative A of the coupled
#325 / #326 selection. **This story implements that section; it decides
nothing.** Where this body and §4 differ, §4 wins.

Three facts read before writing:

- **The hub's half already exists and is not being changed.** The proactive-push
  duty is ratified hub-side (owner ruling 2026-07-23); `/qa-mine`'s selection
  screen, its ledger dedupe and the hub's sweep gate are untouched. §4.2 —
  emission is the duty, promotion stays where it is.
- **The kit holds no write path to the hub**, `policy/kit/README.md:10-12`, and
  this story adds none. The emission is a file in the consumer's own tree.
- **The install script manages five artifacts today**, `policy/kit/install.sh:59-113`.
  The emission directory and its writer are new, and the script is idempotent
  by contract.

## Acceptance criteria

**1 — The duty is stated in the managed block, which is the carrier of record.**
Given `policy/kit/templates/claude-md-block.md`,
when the kit installs or refreshes,
then the block states the duty in the terms of §4.1 — any sitting producing an
investigation finding, reversal, correction or design decision writes ONE
staging-candidate emission in the same sitting, unasked;
and it appears **in the managed block**, not only in
`.claude/skills/consult-first/SKILL.md` — `specs/spec-client-kit/SPEC.md` §2
refuses skill-as-sole-carrier.

**2 — Emissions land in a committed, consumer-owned directory.**
Given a kit install,
when the install completes,
then `policy/emissions/` exists, is **committed** (no `.gitignore` entry), and
emissions are written as `policy/emissions/<YYYY-MM-DD>-<slug>.md`;
and the directory's own README states why this answers the location axis
**oppositely** to `policy/shape.md` — source sensitivity, per §4.3 — so the next
carrier facing the axis reads the discriminator rather than the outcome.

**3 — The format is the five fixed fields, in plain register.**
Given an emission,
when it is written,
then it carries date, repo, trigger (what happened), the learning, and proposed
grain (lesson / topic line / glossary delta);
and the writer refuses or flags vocabulary internal to the hub, per §4.4 —
plain register is part of the format, not advice.

**4 — Nothing promotes, and nothing writes the hub.**
Given any emission act,
when it completes,
then no write is made to any hub path and no recall surface is touched; the
emission is a durable artifact in the consumer's own tree and the hub's gate
remains the sole promotion path — §4.2.

**5 — The absence is visible and is never gated.**
Given a sitting that produced a durable learning and emitted nothing,
when the lane read runs,
then the absence is **reported**, with no act blocked, no commit refused and no
merge withheld — §4.5. A check that denied on this criterion fails it.

**6 — The writer exists and makes the duty cheap to obey.**
Given a sitting holding a durable learning,
when it invokes the kit's emission writer,
then the file is created in one act with the five fields scaffolded, and the
path is printed as an in-session receipt.

**7 — The install-test fixture covers the new artifact.**
Given `policy/kit/test/install-test.sh`,
when it runs,
then it asserts the emission directory's presence, its **absence** from
`.gitignore`, the managed-block clause, and that the writer produces a
conformant five-field file.

## Story questions (not criteria)

- **Whether the §4.5 lane read is one read or per-lane.** Carried as
  `specs/spec-client-kit/SPEC.md` §7 question 2. A per-lane answer is the
  enumeration shape this repository refuses elsewhere, and a single read has no
  obvious home yet — **cannot-determine**, so it is a question and not a
  criterion. Criterion 5 binds only that the absence is reported and not gated.
- **How "produced a durable learning" is recognised by the lane read.** The
  judgment is explicitly one §4.5 says no mechanism can make; what the read
  keys on instead is unverified and is not asserted here.
